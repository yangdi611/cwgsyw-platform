**目标：** 将前端审计 finding 转成可执行工作包、可验证证据和可回滚变更。

## 1. 结论

方案可落地，但不采用 81 个入口页一次性重画，也不进行全库正则替换。推荐边界是：

1. 先隔离共享页面模板和滚动边界。
2. 再按列表、详情/表单、特殊工作区和低频模块分批迁移。
3. 每批只改一个可验证边界，并独立运行 impact、静态门禁、真实点击和视觉验收。
4. API、权限、路由、query keys、业务状态机、数据库和领域工作区交互保持不变。

WP-01 共享模板、WP-02 全局 Shell、WP-03 列表试点、WP-04 列表批量迁移、WP-05 详情/表单、WP-06 特殊工作区和 WP-07 低频模块均已完成各自合同要求并标记为 `VERIFIED`；当前进入 Review/Acceptance 收口阶段。

## 5. 可实施性检查

| 检查项 | 结论 | 处理方式 |
|---|---|---|
| 是否需要后端改动 | 否 | 所有变更限定在前端外壳、组合和状态呈现 |
| 是否需要改路由/API/query | 否 | Prompt 和验收均列为硬性不变量 |
| 是否存在高风险共享组件 | 是 | `PageHeader` 47 个直接调用方、23 条流程、CRITICAL；新增隔离模板 |
| 是否可以一次性迁移 | 不建议 | 按工作包拆分，每批可独立回滚 |
| 是否可自动全库替换 | 不可 | 保留领域差异，禁止正则替换圆角、标题、Button 和 table |
| 是否具备运行时验证条件 | 部分具备 | development 前端、登录态、目标数据和未占用端口是前置条件 |
| 当前最大证据缺口 | 否 | WP-00～WP-07 的代码、静态、授权真实加载和三视口证据已完成；剩余工作仅为独立 Review/Acceptance 和合并决策 |

## 6. 变更预算

每个工作包开始前必须写出本批的“允许变化”和“禁止变化”：

**允许变化：** 外壳组件、CSS class、标题/操作槽位、状态组件组合、Dialog/按钮外观、响应式断点和滚动边界。
**禁止变化：** API 路径和方法、请求体/响应解析、React Query key、权限资源和守卫、路由/动态参数/重定向、业务字段与状态机、数据库、领域画布算法。

当一个页面需要超过两个专属例外 prop 才能接入共享模板时，暂停该批，重新评估抽象边界，不继续堆叠条件分支。

## 7. 证据与状态规则

证据只能使用以下状态：

- `PASS`：命令或真实操作已经执行，结果可复核。
- `FAIL`：本次变更导致失败，必须修复或回滚。
- `BASELINE_FAIL`：基线已有失败，本次未扩大；必须保留原始输出。
- `BLOCKED`：外部环境/授权/数据阻塞，记录复现证据和替代方案。
- `NOT_RUN`：尚未执行，不能写成通过。

代码已存在不等于工作包完成；Prompt 已准备不等于实现完成；静态扫描通过不等于运行时验收通过。
