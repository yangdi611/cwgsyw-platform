# 前端页面统一化实施规格 v1.0

**状态：** 可实施

**基线分支：** `codex/frontend-style-unification`

**运行环境：** `development`

**范围基线：** 81 个 `page.tsx` 入口、全局 Dashboard Shell、任务/Wiki/CMDB 空间等下沉业务组件。

## 1. 产品目标

把平台前端收敛为可预测的 B2B 运维工作台体验：

- 普通列表页有稳定的标题、筛选、工具栏、数据区和状态反馈。
- 详情页有稳定的返回、标题、状态、操作和关联信息层级。
- 表单页有稳定的字段分组、校验提示、保存/取消和未保存状态。
- 工作台页有稳定的指标、业务面板和快捷入口组合。
- 拓扑、BPMN、Wiki 图谱、空间布局、文件预览等复杂页充分利用宽度，不被普通页容器限制。
- 桌面、平板、手机都不会出现操作遮挡、双滚动条或主操作不可达。

## 2. 不变量

以下行为在统一化过程中必须保持不变：

| 范畴 | 不变量 |
|---|---|
| 路由 | 现有路由、动态参数、重定向和面包屑解析保持兼容 |
| API | 请求路径、HTTP 方法、响应解析、分页和筛选参数保持兼容 |
| Query | React Query key、缓存失效和轮询语义不因视觉重构改变 |
| 权限 | 权限判断、路由守卫、按钮显隐和后端鉴权保持原有语义 |
| 领域交互 | CMDB、Workflow、Wiki、文件、空间布局的核心交互和数据模型不变 |
| 状态 | 保存、提交、审批、发布、归档、删除等状态机不改变 |
| 数据 | 本任务不修改数据库、migration、后端 DTO 或业务数据 |

## 3. 页面模板合同

### 3.1 普通页面容器

建议新增或整理以下共享组件：

| 组件 | 职责 | 禁止承担 |
|---|---|---|
| `PageShell` | 普通页的宽度、间距、垂直节奏 | API、权限和业务状态 |
| `FormShell` | 表单页内容宽度和底部操作边界 | 字段校验和提交逻辑 |
| `WorkspaceShell` | 全宽页面、高度和画布滚动边界 | 画布领域算法 |
| `DetailHeader` | 返回、标题、状态、更新时间、操作槽位 | 详情数据请求 |
| `WorkspaceToolbar` | 工作区工具栏高度、返回和操作分组 | 拓扑/BPMN/编辑器行为 |

可以复用已有 `PageHeader`、`FilterBar`、`Toolbar`、`DataTable`、`DetailDrawer`、`Pagination`、`LoadingState`、`ErrorState` 和 `EmptyState`；不为单个页面创建重复模板。

### 3.2 标准列表页

```text
PageShell
  -> PageHeader（标题、说明、主操作）
  -> FilterBar（查询和筛选）
  -> Toolbar（批量操作/视图操作）
  -> DataTable 或领域列表
  -> Pagination / LoadingState / ErrorState / EmptyState
  -> DetailDrawer（适用时）
```

列表页必须：

- 保留业务列和权限控制。
- 对 loading、error、empty 提供明确恢复路径。
- 不使用裸 `<h1>` 作为新增标准列表标题。
- 不因迁移顺手改 URL 筛选参数、分页默认值或 API 查询键。

### 3.3 标准详情页

```text
PageShell
  -> DetailHeader
  -> 主信息/状态摘要
  -> Tabs 或 Sections
  -> 关联对象、历史、审计和操作反馈
```

详情页必须：

- 首屏能返回上一级或列表。
- 状态标签和危险操作语义一致。
- 详情数据不存在、无权访问和网络失败要区分展示。

### 3.4 表单页

```text
FormShell
  -> 返回 + PageHeader/DetailHeader
  -> 字段分组或步骤
  -> 字段级错误 + 页面级错误
  -> 保存/取消/提交操作
```

表单内容宽度由模板决定：普通表单 `max-w-2xl`，复杂编辑 `max-w-4xl`，画布型编辑器使用 `WorkspaceShell`。不允许每个页面随意新增不同的最大宽度。

### 3.5 特殊工作区

适用：CMDB 拓扑、2D、空间布局、影响分析、BPMN、Wiki 图谱、文件预览、任务模板设计器。

```text
WorkspaceShell
  -> WorkspaceToolbar
  -> 可折叠左侧资源/筛选面板
  -> 中央画布、编辑器或预览
  -> 可折叠右侧属性/详情面板
```

特殊工作区必须统一：

- 工具栏高度、返回按钮、标题和主操作位置。
- 画布剩余高度和横向空间计算。
- loading、error、empty、无权和移动端不可编辑提示。
- 面板折叠后不破坏键盘可达性和主要操作。

特殊工作区可以保留：

- ReactFlow、bpmn-js、Markdown 编辑器和空间布局的领域控件。
- Wiki 的独立目录侧栏。
- CMDB 概览的模型组目录和颜色编码。
- 任务分析的统计表格和筛选语义。

## 4. 组件迁移边界

### 允许

- 新页面和被本批触及的组件优先使用 `components/v2` + `components/shared`。
- 在不改变行为的前提下，把固定 overlay 迁移到现有受控 Dialog。
- 将手写 loading/error/empty 文案接入共享状态组件。
- 将旧按钮包在兼容适配器中，逐批迁移 variant，不做全库替换。

### 禁止

- 在一个 PR 中重命名/删除整个 `components/ui`。
- 用正则批量替换所有 `rounded-*`、`bg-muted`、`<h1>` 或 Button import。
- 为了视觉统一修改后端字段名、状态名、接口地址或权限资源。
- 把所有页面强制包进 Card，或把画布页强制变成普通窄容器。
- 给共享组件增加大量单页例外 props；超过两个例外时重新评估抽象边界。

## 5. 视觉和可访问性合同

- 新增样式优先使用 V2 token；颜色只表达层级、状态和交互，不做装饰性渐变堆叠。
- 按钮使用现有 lucide 图标；图标按钮提供 `title` 或 `aria-label`。
- 标题层级、表单 label、错误提示、Dialog 标题和键盘焦点必须可访问。
- 文本不得溢出父元素；操作区在 390px 宽度下必须换行或进入更多菜单。
- 普通卡片圆角不超过既有设计系统上限；不新增营销页式 hero、装饰性 orb 或无业务意义的阴影。

## 6. 代码质量合同

- 页面超过 600 行且需要增加主要行为时，先提取业务组件或 hook。
- 新增 TypeScript 代码不使用无理由的 `any`。
- 修改共享组件前先读取调用方并执行 upstream impact。
- 人工编辑使用 `apply_patch`，不使用脚本覆盖文件。
- 提交前执行 `detect_changes()`，确保符号和执行流影响符合当前工作包。
