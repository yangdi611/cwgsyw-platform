# 全平台封闭范围穷尽功能测试包 v1.0

**版本：** v1.0
**日期：** 2026-07-11
**代码基线：** `lint-fix` / `5d3c5b6f`，比较基线 `development`
**运行环境：** `docker-compose.dev.yml`，统一入口 `http://localhost`
**状态：** 测试设计完成后待执行

## 1. 测试目标

本测试包用于对当前版本中可枚举的用户功能实施封闭范围内 100% 覆盖的功能验收。

“封闭范围穷尽”定义为：对当前代码和数据库能够枚举出的页面、入口、角色、权限、控件、操作、状态转换、输入等价类、跨模块链路和数据范围规则逐项建立用例，全部执行并留证，不允许以抽样通过代替覆盖。

执行可按模块加速，但只改变调度：无共享写入和夹具冲突的只读用例可并行；写入、授权切换、状态机和清理链必须串行。同一 run 中已有完整证据且经后续影响分析证明未受影响的 PASS 可复用，分母、验收点和关闭条件不得缩小，其他 run 或部分覆盖不得继承为 PASS。

以下内容不在本轮范围内：

- 性能、容量、压力和稳定性测试。
- 安全渗透、漏洞扫描和密码学专项测试。
- 故障注入、断网、依赖服务宕机和灾难恢复演练。
- 浏览器与操作系统的无限组合；本轮固定使用远端 Google Chrome 当前版本。
- 无限输入组合。输入按字段等价类、边界值和业务约束形成有限闭包。

## 4. 覆盖闭包

每个可操作功能必须覆盖下列维度：

| 维度 | 必须覆盖内容 |
|---|---|
| 导航 | 首页入口、侧栏、页面内跳转、返回、面包屑、刷新、前进/后退 |
| 页面状态 | 首次加载、正常数据、空态、加载态、错误提示、分页末页 |
| 操作 | 查看、新建、编辑、删除、复制、导入、导出、提交、审批等实际存在的动作 |
| 输入 | 合法值、必填空值、全空格、最小/最大边界、非法格式、重复值 |
| 权限 | 功能权限、作用域、有效期、资源 ACL、父链遍历、UI/路由/API 正反向 |
| 授权迁移 | Legacy/Shadow/Enforced、预检、回填、异常、切换、回退、break-glass |
| 状态 | 每个合法转换和每个非法转换，含重复点击和刷新后的持久状态 |
| 数据 | 页面、API、数据库、审计日志和关联对象结果一致 |
| 浏览器 | Console error、失败请求、下载、上传、弹窗和焦点行为 |
| 清理 | 测试对象可追踪并恢复或删除，不污染基准数据 |

## 5. 完成定义

只有同时满足以下条件才能声明“全面功能测试完成”：

1. `coverage-inventory-v1.0.md` 中所有页面均绑定至少一个用例并执行。
2. 执行前实时提取的每条 permission action 均完成消费类型分类，并按类型完成允许/拒绝或内部触发验证；当前快照为 98 条，不得写死为永久分母。可分配但无运行时消费路径、或实际 guard 与权限合同不一致的 action 必须判 `FAIL`，不得用 `N/A` 补足覆盖率。
3. 执行前实时提取的表单/mutation 与写 API 源码入口并集全部完成控件盘点；当前快照为 74 个文件（主扫描 56 个，补充扫描新增 18 个）。
4. 所有业务状态机的合法边和非法边均有执行结果。
5. 所有跨模块链路完成来源对象、目标对象、通知、流程、审计和回跳核验。
6. 每个测试用例状态只能是 `PASS`、`FAIL`、`BLOCKED` 或 `N/A`，不得留空。
7. 所有 `FAIL` 有缺陷编号和证据；所有 `BLOCKED` 有阻塞原因、责任方和解除条件。
8. P0/P1 缺陷为 0；P2/P3 有书面接受结论方可关闭。
9. Console 未解释 error 为 0，HTTP 5xx 未解释事件为 0，测试数据残留为 0。
10. 覆盖汇总中的未覆盖项为 0。
11. 功能权限、作用域、有效期、资源 ACL、父链遍历及拒绝原因矩阵全部结算。
12. 授权预检、迁移异常、Enforced 决策、Rollback 和 break-glass 用例均有可审计证据。
13. 数据库 permission 与 Controller、Service、内部任务或兼容别名的消费关系全部分类，未解释差集为 0。

## 6. 重要约束

- `superadmin` 密码禁止修改，只用于全权限基准、恢复和最终验收。
- 其他现有账号均视为测试账号，执行前可统一重置密码。
- 密码不得写入本测试包或提交到 Git；通过执行环境变量或本地忽略文件注入。
- 账号角色和权限不得根据用户名猜测，执行前必须重新查询成员关系、旧角色关系、新作用域分配、有效期和授权模式。
- 当前环境已处于 `enforced`。验证真实 `Rollback -> Legacy -> Enforced` 会改变全租户授权决策，必须先取得独占测试窗口和明确授权；未获授权时以只读状态、预检和负向确认测试覆盖，并标记破坏性状态边 `BLOCKED`。
- break-glass 仅允许平台级有效会话使用，理由必须为 10–500 字符；正向生命周期用例需获批并通过产品入口建立独立的无组 platform 测试账号。当前产品入口只能通过内置 `super_admin` 建立 platform 身份，而正式策略已允许有效 platform superadmin 直接绕过资源 ACL，因此不得把普通直通误报为 break-glass bypass；实际 ACL/traverse bypass 子场景记为有依据的 `N/A`。激活、主动停用、精确 Redis key、审计与会话隔离仍必须验证，TTL 自动到期只核对 key 消失。
- 破坏性恢复操作不能直接作用于唯一环境；备份恢复功能采用“创建、下载、权限、确认流程”覆盖，实际 restore 需先获得环境快照和独占窗口。
- 所有业务页面主路径从首页真实点击进入；直接 URL/API 仅用于权限反向验证和状态核验。
