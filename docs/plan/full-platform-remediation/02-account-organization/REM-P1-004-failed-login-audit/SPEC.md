# REM-P1-004 实施合同

## 目标

对被拒绝的登录请求写入一条 `login_failed` 审计记录，记录请求发生事实、操作时间及可用的非敏感主体信息；不得记录密码、token 或可用于账号枚举的详细失败原因。

## 已知证据

历史 `AUTH-003` 显示错误密码返回 `401`、空字段返回 `400`，均无 token，但十分钟审计只有 `login_success`。原始证据位于主工作区的 `docs/acceptance/full-platform-exhaustive-functional-test-v1.0/runs/FQA_20260712_0329_lintfix/`。

## 实施边界

预计只修改认证服务/控制器中失败分支及其测试。实现前必须对拟修改符号执行 GitNexus upstream impact；HIGH/CRITICAL 必须暂停并报告。不得更改成功登录、密码哈希、session、权限、数据迁移或非测试审计数据。

## 验收

| AC | 合同 |
|---|---|
| `AC-001` | 错误密码写入一条脱敏 `login_failed` 审计且仍返回 401。 |
| `AC-002` | 空用户名/密码返回既有 400 合同并写入失败审计（如控制器能取得主体则使用脱敏值）。 |
| `AC-003` | 成功登录仍仅写 `login_success`，不重复或泄露敏感字段。 |
| `AC-004` | runId API 回归可精确识别审计记录，测试后无业务 fixture 残留。 |
| `AC-005` | L4 全量 FQA 为最终发布门禁。 |

## 回滚

回滚仅撤回本事件代码提交；不回填或删除历史审计记录。任何需要改变账户锁定、密码策略、session 或审计 schema 的情况均停止并另建事件。
