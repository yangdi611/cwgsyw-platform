# REM-P2-030 实施合同

## 目标

使已保存的 `fixedDocxTable` 行以相同顺序、列值和可读布尔值出现在变更文档导出结果中；无 DOCX 模板时，程序化 DOCX 回退也不得静默丢失动态表格字段。

## 合同

- 仅对 `fieldType=table` 且 `tableMode=fixedDocxTable` 生效；非表格字段和现有 DOCX 占位符行为保持兼容。
- DOCX 模板路径和程序化回退路径都必须呈现表格字段标题、列标题和持久化行，行顺序与 `fieldsData` 数组一致。
- 文本、数字、日期、枚举、textarea 保持其保存值；checkbox 以用户可读且稳定的值呈现；空单元格与空行的呈现规则必须明确且可测试。
- 不存在表格行时，导出仍成功且不虚构行；不得抛出空指针或产生损坏 DOCX。
- 导出权限、文档状态限制、tenant 隔离、模板下载/上传权限和现有文件名/MIME 合同不变。

## 验收

| ID | 合同 |
|---|---|
| AC-001 | 含三行、不同单元格类型的固定表格字段在 DOCX 模板导出中按保存顺序出现。 |
| AC-002 | 无 DOCX 模板时程序化 DOCX 回退仍输出该表格，且不丢行或列。 |
| AC-003 | 空行、空单元格、checkbox 和长文本导出稳定且文档可打开。 |
| AC-004 | 无表格字段和普通导出路径回归通过；权限/状态/tenant 拒绝语义不变。 |
| AC-005 | L2 API 导出与 L3 真实页面下载均验证文件内容；所有 runId 文档和通过产品 API 创建的测试模板精确清理。 |

## 影响与回滚

实施前必须对拟修改的 `ExportService`、`ChangeDocTemplateService.fillDocx` 及相关导出控制器逐一执行 GitNexus upstream impact。导出属于用户交付内容，若结果为 HIGH/CRITICAL，必须先报告影响范围再修改。

回滚仅还原本事件提交；不迁移历史文档，不扫描、删除或改写对象存储中的既有模板。
