# 统一任务平台实施文档索引

**状态：** 实施准备中  
**适用项目：** cwgsyw-platform  
**总目标：** 用统一任务、表单、计划、提交、审批和统计模型替换旧运维任务与独立日报，实现无长期兼容垃圾的预上线硬切换。

## 2. 权威优先级

出现冲突时按以下优先级处理：

1. 用户在当前实施会话中的最新明确指令。
2. 仓库根目录及目标目录适用的 `AGENTS.md`。
3. 本目录 `PRD.md` 的产品目标与验收边界。
4. 本目录 `SPEC.md` 的技术不变量。
5. `DATA-MODEL.md`、`API-UI-CONTRACT.md`、`SCHEMA-CUTOVER.md`、`SCHEMA-OBJECT-LEDGER.md` 和 `TEST-ACCEPTANCE.md` 的专属合同。
6. `IMPLEMENTATION-PLAN.md` 的实施顺序。
7. 仓库中较早的流程增强、运维日历和日报文档。

本方案明确覆盖以下旧规划边界：

- 日报不再作为独立业务模块，改为内置任务模板。
- 运维日历不再拥有独立任务模型，只保留单页面时间视图与排班/节假日能力。
- 流程中心不再保留两套用户待办页面或旧审批接口。
- 不为旧日报和旧运维任务保留兼容 API、双写、双读或旧 schema。

## 3. 已冻结实施决策

为避免实施过程中反复停下来选择，除非用户明确修改，采用以下默认决策：

### 3.1 产品与导航

- 一级入口使用“我的工作”“任务中心”“运维日历”“流程管理”。
- “我的工作”是普通用户默认工作入口。
- 运维日历保留独立入口和现有单页面多视图风格。
- 日报只提供统一任务页面的快捷筛选或首页卡片，不保留独立 CRUD 页面。

### 3.2 模板与任务

- 正式任务必须绑定已发布任务模板版本。
- 快速一次性任务使用内置“简易任务”模板，不允许绕过版本模型保存任意无版本表单。
- 模板管理员可在授权范围内创建模板；发布需要 `task_template:publish`。
- 多人协作首期共同完成一份任务提交，不实现每人独立区块。
- 模板或计划的审批方案只允许有相应权限的创建者覆盖。

### 3.3 审批

- 审批默认提供“通过”“退回修改”；“终止”需方案显式启用。
- 退回修改必须填写理由，可选字段级和附件级意见。
- 执行人不强制逐条回复意见，但重新提交页面必须展示未处理意见。
- 日报审批方案允许按组或计划分别配置，不做全租户单一日报绑定。

### 3.4 统计

- 第一版自定义统计支持单模板完整能力。
- 跨模板统一指标、权威来源和周期引用在后续工作包实现，但数据模型首期预留。
- 文字首期支持明细、搜索和人工标签；AI 分类与摘要后置。
- 附件首期支持元数据、文件列表和图片墙；OCR 与正文解析后置。
- 组/租户共享看板和 Excel/CSV 导出纳入统计阶段。

### 3.5 数据与切换

- 保留现有数据库、V1-V79 migration 历史和非目标业务数据，通过 V80+ 增量升级。
- “保护现有数据库”是升级过程中的防误删要求，不是所有历史表列永久保留的结论。
- 旧日报、旧 `ops_schedule_*` 及其专属流程/通知/配置数据已明确授权在消费者切换后定向删除。
- WP-09/WP-10 的 schema 清理范围是统一任务目标域、旧日报、旧 `ops_schedule_*`、它们的专属关联物、共享表中的精确旧任务目标行，以及明确只服务一次性切换的重复模型。用户、RBAC、CMDB、设备、Wiki、共享文件和通知等其他正式业务模块的 schema 必须保持不变。
- 迁移、灰度、兼容、影子比对和旧 ACL/RBAC 对象只有在能证明其仅服务一次性切换、且不承载其他正式业务模块能力时，才可连同过渡消费者删除。
- 不新增“临时兼容 Controller”或旧路由重定向页。
- 代码与 schema 的旧实现删除是完成条件，不是后续可选清理。
- 旧任务域及明确过渡对象必须有正式消费者；其他正式业务模块的表、列、索引、触发器、函数、配置、权限、API 和页面不属于本项目清理范围。
- 表级 `KEEP` 只确认业务集合继续存在，不代表历史列整体保留；列级没有终态证据同样删除。

## 4. 目标终态

```text
我的工作
  ├─ 待执行（统一任务实例）
  ├─ 待审批（Flowable 审批节点）
  ├─ 我发起的
  ├─ 抄送我的
  └─ 已完成

任务中心
  ├─ 任务列表
  ├─ 任务模板
  ├─ 任务计划
  └─ 任务统计

运维日历（单页面）
  └─ 月 / 周 / 列表视图切换

流程管理
  ├─ 审批方案
  ├─ 流程实例
  ├─ 流程设计
  └─ 流程统计
```

核心数据流：

```text
任务模板版本
  → 任务计划
  → 任务实例
  → 草稿
  → 不可变提交版本
  → 可选审批轮次
  → 当前有效提交
  → 字段事实 / 指标事实
  → 自定义统计看板
```

## 5. 实施前置条件

- 阅读适用的 `AGENTS.md` 和代码质量规则。
- 检查工作树，保护用户已有修改。
- 确认 GitNexus 索引新鲜；编辑任何函数、类或方法前执行 upstream impact。
- 所有 migration 自动化验证使用隔离 Testcontainers；真实环境升级前确认连接与备份。
- 不清空、重建或整体替换现有数据库。
- 按 `IMPLEMENTATION-PLAN.md` 一次只推进一个可验证工作包。
- 每次开始和结束更新 `IMPLEMENTATION-STATUS.md`。

## 6. 完成定义

只有同时满足以下条件，统一任务平台才算完成：

- `TEST-ACCEPTANCE.md` 中所有必须验收项通过。
- 新任务、日报模板、审批退回、CI 层级选择和统计链路可用。
- 跨模板/跨周期汇总、权威来源、目标阈值和整改/复查自动化可用。
- 运维日历只消费统一任务接口。
- 构建产物中不存在旧日报页面/API/服务/权限。
- 构建产物中不存在旧运维任务、规则、模板、统计、素材 API 和领域类。
- 构建产物中不存在重复 workflow 用户待办页面和旧审批接口。
- V1 到最新版本全新安装以及 V79 到最新版本增量升级都达到相同终态，旧日报和旧运维任务表最终不存在。
- `SCHEMA-OBJECT-LEDGER.md` 覆盖旧任务域、关联共享目标行和明确过渡对象；所有清理对象均有旧任务替代或过渡证据，其他正式业务模块对象保持不变。
- 前端 lint/typecheck、后端 compile/test 和关键交互验收通过。
- `detect_changes()` 仅显示预期模块和执行流影响。
- `IMPLEMENTATION-STATUS.md` 包含最终证据与剩余非阻塞事项。
