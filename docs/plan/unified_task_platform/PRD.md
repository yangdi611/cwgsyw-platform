## 1. 文档目的

本文档用于定义 cwgsyw-platform 下一阶段的统一任务平台产品方案，将当前分散在运维日历、流程中心、工作日报及部分业务模块中的任务、提交、提醒、审批和统计能力进行统一。

本文档重点回答以下问题：

1. 高度定制化任务如何创建、下发、执行和提交。
2. 一次性任务与周期性任务如何使用同一模型。
3. 日报、周报、季报、巡检、临时填报如何通过模板表达。
4. 任务提交后如何进入可选审批，并形成退回修改闭环。
5. 自定义表单中的数字、选项、文字、表格、附件如何查询和汇总展示。
6. 不同模板、不同统计周期、不同维度的数据如何安全地进行统一或独立统计。
7. 运维日历、任务中心和流程中心分别承担什么职责。

本文档属于产品需求定义，不直接规定最终数据库表名和 API 结构。详细技术方案在 PRD 评审通过后另行形成 SPEC。

## 2. 背景

### 2.1 当前能力

当前平台已经具备以下基础：

- 运维日历支持一次性任务、周期规则、任务实例、执行人、参与人、提醒、逾期升级、检查项、日志和关联对象。
- 流程中心支持流程定义、流程模板、流程实例、业务流程绑定、待办查询、审批通过和拒绝。
- 工作日报支持完成事项、问题、明日计划、工时、关联 CI、提交审批和审批状态。
- 变更文档支持模板字段、动态表单、结构化字段数据、表格字段及后端校验。
- 通知中心支持站内通知以及跳转到相关业务对象。

### 2.2 当前问题

现有能力按照功能模块分别建设，逐渐出现职责重叠和体验割裂：

1. 运维日历不仅展示日期，还拥有独立任务创建和执行能力。
2. 流程中心同时出现“待办中心”和“我的任务”，但两者主要承载审批节点，名称容易被理解为业务任务。
3. 工作日报本质上是“按工作日生成、要求填写固定表单、可进入审批”的周期任务，却作为独立业务模块存在。
4. 运维任务的检查项只能覆盖较轻量的输入，无法充分表达复杂表单、字段联动、表格、附件要求和版本化。
5. 当前流程绑定主要按业务类型统一绑定，不足以支持不同任务模板选择不同审批方案。
6. 自定义表单数据缺少统一的统计语义，数字、文字和附件无法按配置形成稳定看板。
7. 日报、周报、季报可能采集不同字段、使用不同维度，不能依赖固定报表页面解决。

### 2.3 产品机会

平台可以在已有调度、动态表单、流程和通知能力基础上，建设一套面向运维协作场景的“可配置任务应用平台”：

- 创建者定义要做什么、填写什么、上传什么、何时完成。
- 系统按一次性或周期性规则生成任务并分配执行人。
- 执行人填写结构化表单、提交附件并完成任务。
- 需要审批时，由流程引擎处理审批节点和退回修改。
- 审批后的结构化数据进入统一统计体系。
- 运维日历按时间展示任务，统计中心按指标和维度展示结果。

日报、周报、季报、巡检、合规检查、资料收集等场景由不同任务模板表达，而不是继续建设彼此独立的固定模块。

## 3. 产品定位

### 3.1 产品定义

统一任务平台是一套面向组织内部工作下发、周期执行、结构化填报、附件提交、审批闭环和数据分析的配置化平台。

平台核心链路如下：

```text
任务模板
  ↓ 定义任务说明、表单、附件和完成条件
任务计划
  ↓ 定义时间、执行人、提醒和审批方案
任务实例
  ↓ 执行人填写、上传、保存草稿
任务提交版本
  ↓ 无需审批直接完成，或发起审批
审批实例
  ↓ 通过、退回修改或终止
有效数据
  ↓ 指标提取、分类、查询和统计
统计方案 / 看板 / 导出
```

### 3.2 模块职责

| 模块 | 核心职责 | 不承担的职责 |
| --- | --- | --- |
| 任务中心 | 模板、计划、任务实例、执行、提交、提醒、统计配置 | 不自行实现审批流引擎 |
| 审批中心 | 审批方案、审批待办、审批记录、流程实例 | 不保存任务表单的唯一业务数据 |
| 运维日历 | 按日期展示任务实例、状态和快捷入口 | 不单独维护另一套任务模型 |
| 我的工作 | 聚合待执行、待审批、我发起、抄送和已完成事项 | 不改变底层任务与审批对象边界 |
| 统计中心 | 自定义指标、维度、筛选、看板和下钻 | 不绕过源任务的数据权限 |

### 3.3 核心边界

业务任务与审批待办是两个不同对象：

- 业务任务表示某人需要实际完成的工作。
- 审批待办表示某审批人在流程某个节点需要做出的决定。
- 一个业务任务可以没有审批，也可以产生一轮或多轮审批。
- 任务状态与审批状态必须分别保存和展示。

## 4. 产品目标

### 4.1 总目标

建设一套统一、可配置、可追溯、可统计的任务平台，使管理员或授权创建者能够在不开发新业务模块的情况下配置常见任务应用。

### 4.2 用户目标

面向任务创建者：

- 可以通过表单设计器创建高度定制化任务内容。
- 可以设置一次性或周期性任务、执行人、截止时间和提醒。
- 可以选择无需审批或配置审批方案。
- 可以查看任务完成情况、退回情况和统计结果。

面向执行人：

- 在统一工作台查看自己要完成的任务。
- 按预设表单填写内容、上传附件、保存草稿并提交。
- 被退回时清楚看到拒绝理由、问题字段和历史提交。
- 修改后重新提交，无需重新创建任务。

面向审批人：

- 在统一审批待办中查看业务摘要、完整提交内容和附件。
- 可以通过、退回修改或按权限终止。
- 退回时必须说明理由，并可针对字段或附件提出意见。
- 可以查看此前审批轮次和修改差异。

面向管理者和分析人员：

- 可以按自定义时间范围、组织、人员、模板、状态和业务维度统计。
- 可以针对数字、选项、文字、表格和附件使用适合的汇总方式。
- 可以创建可复用看板并下钻到原始任务。
- 可以区分系统计算值、原始上报值和人工汇总值。

### 4.3 平台目标

- 统一一次性任务、周期任务、日报和自定义填报的领域模型。
- 复用现有流程引擎，不再为每种任务编写独立审批逻辑。
- 复用现有调度、通知和动态字段经验，形成通用能力。
- 保持模板和历史提交可版本化、可审计、可回溯。
- 为后续自动化联动、智能分析和大屏展示提供结构化数据基础。

## 5. 非目标

本 PRD 第一阶段不追求完整低代码应用开发平台，以下内容不作为首期目标：

1. 不允许普通用户编写任意 JavaScript、SQL 或服务端脚本。
2. 不实现任意复杂数学语言，公式仅支持受控函数和字段引用。
3. 不要求所有日报、周报、季报共享相同表单或相同统计维度。
4. 不强制把既有 Wiki、变更文档等专业业务对象全部迁移成通用任务。
5. 不在首期实现 OCR、附件内容全文解析、AI 自动分类和 AI 自动决策。
6. 不在首期实现完整的数据仓库或跨租户数据分析。
7. 不允许统计看板突破原任务、附件和组织数据权限。
8. 不在首期支持任意复杂 BPMN 设计；优先使用审批方案模板。
9. 不保留旧日报和旧运维任务的历史开发数据；系统尚未上线，统一任务平台切换时直接使用新数据模型和初始化种子。

## 6. 设计原则

### 6.1 模板完全可配置，运行实例保持稳定

创建者可以自由组合任务内容，但已生成任务必须绑定具体模板版本。模板更新不能改变历史任务和已提交内容。

### 6.2 表单数据是业务事实，流程数据是审批事实

任务提交保存表单、附件和关联对象；流程保存节点、审批人、意见和决策。流程不能成为表单数据的唯一存储位置。

### 6.3 统计配置化，但计算口径必须显式

用户可以自定义统计值、维度和展示方式，但必须声明数据来源、聚合方式、时间口径和有效数据范围。

### 6.4 原始数据与汇总数据分离

日报原始巡检次数、周报自动汇总值、周报人工上报值必须能区分来源，避免重复统计和覆盖原始事实。

### 6.5 权限继承且最小暴露

任务、提交、审批、看板和附件均遵循租户、组织范围和资源权限。汇总结果和下钻明细使用同一权限边界。

### 6.6 审计优先

模板发布、计划变更、任务生成、表单修改、附件增删、提交、审批、退回、重新提交和统计口径变更均可追溯。

### 6.7 配置体验优先于技术细节

创建者配置“谁执行、填什么、何时交、谁审批”，不直接面对 Cron、BPMN XML、流程变量和数据库字段。

## 7. 术语与核心对象

| 术语 | 定义 |
| --- | --- |
| 任务模板 | 定义任务说明、表单、附件、完成条件和默认策略的可复用配置 |
| 模板版本 | 任务模板发布时形成的不可变快照 |
| 任务计划 | 基于模板配置时间规则、执行对象、提醒和审批方案 |
| 任务实例 | 某个执行人或协作组在某个时间需要完成的具体工作 |
| 表单定义 | 字段、布局、校验、条件和计算规则的结构化定义 |
| 提交版本 | 执行人某次正式提交的表单数据、附件和关联对象快照 |
| 审批方案 | 审批节点、审批人来源、通过策略、退回策略的版本化配置 |
| 审批轮次 | 同一任务从提交到通过或退回的一轮审批过程 |
| 指标 | 可计算或可聚合的业务量，例如巡检次数、故障数量、工作时长 |
| 维度 | 用于分组、筛选和下钻的分析角度，例如时间、组、人员、CI、风险等级 |
| 统计方案 | 数据源、指标、维度、筛选、口径和展示组件的保存配置 |
| 权威来源 | 某个指标用于正式统计的主数据来源 |

## 8. 用户角色与权限

### 8.1 产品角色

| 角色 | 主要能力 |
| --- | --- |
| 平台管理员 | 管理平台级字段类型、审批模板、数据安全和系统参数 |
| 租户管理员 | 管理租户范围内的任务模板、统计方案和授权 |
| 任务模板管理员 | 创建、编辑、发布、停用和复制任务模板 |
| 任务计划创建者 | 使用已发布模板创建一次性或周期性计划 |
| 任务负责人 | 对任务执行结果负责，可填写、提交和协作 |
| 任务协作人 | 按授权共同填写或上传材料 |
| 审批人 | 处理分配给自己的审批节点 |
| 抄送人 | 只读查看指定任务或审批结果 |
| 统计查看者 | 查看被授权的看板和明细 |

### 8.2 权限原则

- “可以创建模板”和“可以用模板创建任务”是不同权限。
- 创建者只能选择自己有权管理的人员、组和业务范围。
- 审批候选关系与业务审批权限同时满足时才能审批。
- 任务创建者默认可以查看自己创建任务的进度，但不自动获得敏感字段和附件的越权访问权限。
- 字段可配置执行人可见、审批人可见、统计可用和导出可用范围。
- 敏感附件必须继承任务权限，并支持额外访问控制和下载审计。
- 统计结果按当前查看人的权限重新计算或过滤，不能通过聚合接口推断无权访问的数据。

## 10. 核心业务流程

### 10.1 模板创建与发布

1. 模板管理员新建任务模板。
2. 配置任务名称、说明、分类、表单、附件和关联对象。
3. 配置字段校验、条件显示和计算字段。
4. 预览执行人填写页面和审批人查看页面。
5. 保存为草稿并测试填写。
6. 发布模板，形成不可变模板版本。
7. 已发布模板可被创建计划；后续修改需要发布新版本。

### 10.2 一次性任务创建

1. 创建者选择已发布模板。
2. 填写本次任务标题、执行人、计划时间、截止时间和优先级。
3. 选择是否覆盖模板默认提醒和审批方案。
4. 预览任务内容并发布。
5. 系统为执行对象生成任务实例并发送通知。

### 10.3 周期任务创建

1. 创建者选择任务模板。
2. 设置周期规则、生成提前量、截止规则和节假日策略。
3. 设置分配规则：固定人员、固定组、值班人、动态组成员或其他受控来源。
4. 设置生成模式：每人一份、多人协作一份或按组一份。
5. 设置提醒、逾期升级和审批方案。
6. 系统展示未来若干次任务预览。
7. 启用计划后按规则幂等生成任务实例。

### 10.4 任务执行与提交

1. 执行人从“待执行”、通知或日历进入任务详情。
2. 阅读任务说明，填写表单并上传附件。
3. 系统自动保存草稿并校验字段。
4. 执行人点击提交。
5. 系统冻结本次提交版本，并记录模板版本、组织快照和附件清单。
6. 无需审批时任务完成；需要审批时进入审批中。

### 10.5 审批退回与重新提交

1. 审批人查看完整提交内容、附件、历史版本和任务上下文。
2. 审批人选择通过、退回修改或终止。
3. 退回修改时必须填写原因，可标记问题字段或问题附件。
4. 系统通知任务负责人，任务进入待修改状态。
5. 执行人看到审批人、退回时间、退回原因和具体问题位置。
6. 执行人在上一版本基础上修改并重新提交。
7. 系统形成新提交版本和新审批轮次，旧版本及审批意见不可覆盖。

### 10.6 统计方案创建

1. 统计创建者选择一个或多个任务模板作为数据源。
2. 选择时间口径和有效数据范围。
3. 将字段配置为指标、维度、筛选条件、明细内容或附件证据。
4. 配置聚合方式、分组维度、筛选条件和公式。
5. 选择 KPI、图表、表格、文本列表或附件墙等展示组件。
6. 预览结果并检查统计口径说明。
7. 保存为个人看板或共享看板。

## 11. 功能需求

### 11.1 任务模板管理

#### FR-TPL-001 模板基本信息

模板应支持配置：

- 模板名称、编码、分类和描述。
- 使用说明和富文本操作指引。
- 默认标题规则、优先级和可见范围。
- 任务负责人、协作人、抄送人等角色定义。
- 是否允许执行人转交、邀请协作或申请延期。
- 是否允许任务创建者覆盖默认配置。
- 标签、适用组和可使用范围。

#### FR-TPL-002 模板生命周期

模板状态至少包括：

- 草稿：可以修改，不能创建正式任务。
- 已发布：生成固定版本，可创建任务。
- 已停用：不能创建新计划，已有任务继续执行。
- 已归档：只用于历史查询。

模板更新必须发布新版本。计划可选择继续使用已绑定版本或手动升级，不能静默切换。

#### FR-TPL-003 模板复制与内置模板

- 支持复制已有模板作为新模板草稿。
- 系统提供日报、周报、月度巡检、资料收集等内置模板示例。
- 内置模板允许租户复制后自定义，不直接修改系统原始版本。

### 11.2 表单设计器

#### FR-FORM-001 字段类型

首期建议支持：

| 类别 | 字段类型 |
| --- | --- |
| 基础输入 | 单行文本、多行文本、富文本、数字、金额、百分比 |
| 选择 | 单选、多选、下拉、开关、评分、标签 |
| 时间 | 日期、日期时间、时间段、时长 |
| 组织 | 人员、用户组、角色 |
| 运维对象 | CI 范围（模型组、模型、实例）、系统、设备、告警、变更文档等已注册关联对象 |
| 结构化 | 表格、重复区块、分组标题、说明文本 |
| 文件 | 文件、图片、附件集合 |
| 计算 | 公式字段、引用汇总字段 |

#### FR-FORM-002 字段配置

每个字段可配置：

- 字段编码、标题、说明、占位提示和默认值。
- 是否必填、是否只读、是否允许执行人修改。
- 长度、数值范围、精度、格式和正则校验。
- 选项值、选项标签、选项顺序和停用状态。
- 单位、展示格式和空值处理方式。
- 是否允许统计、是否允许导出、是否敏感。
- 执行人、审批人、抄送人和统计查看者的字段可见性。

字段编码在同一模板内唯一。已发布版本的字段编码不可修改。

#### FR-FORM-003 布局配置

- 支持区块、分组、标题、说明和分栏。
- 支持拖拽排序。
- 支持填写页与审批查看页预览。
- 移动端使用单列降级，不因复杂布局无法填写。

#### FR-FORM-004 条件规则

支持受控的条件显示和必填规则，例如：

```text
当“是否发现异常 = 是”时：
  显示“异常说明”和“整改照片”
  并将两者设为必填
```

首期条件来源限于当前表单字段，不执行任意脚本。

#### FR-FORM-005 计算字段

支持同一提交内的受控公式，例如：

```text
巡检通过率 = 正常设备数 / 巡检设备数 * 100
总耗时 = 巡检次数 * 单次平均耗时
```

公式应支持：

- 四则运算、括号和空值处理。
- `SUM`、`AVG`、`MIN`、`MAX`、`COUNT` 等受控函数。
- 当前表单数字字段和表格数字列引用。
- 除零、精度和舍入规则。
- 实时预览及后端重新计算，不能只信任前端结果。

#### FR-FORM-006 表格与重复区块

- 创建者定义固定列和列类型，执行人新增或删除数据行。
- 每列可配置必填、选项、数值范围和统计属性。
- 支持对表格行计数、对数字列聚合、按选择列分类。
- 表格数据保持结构化，不压缩为文本。

### 11.3 附件与关联对象

#### FR-FILE-001 附件要求

附件字段可配置：

- 是否必传、最少和最多数量。
- 允许的文件类型、单文件大小和总大小。
- 图片是否允许拍照上传。
- 附件分类，例如巡检照片、日志文件、整改证明、签字材料。
- 是否需要附件说明。

#### FR-FILE-002 附件版本与权限

- 正式提交时冻结附件清单。
- 重新提交可新增、替换或删除当前草稿附件，但历史提交附件继续保留。
- 附件下载、预览和导出继承任务和字段权限。
- 敏感附件访问必须记录审计日志。

#### FR-LINK-001 关联对象

- 支持关联 CI、设备、告警、变更文档、共享文件及外部链接。
- 创建者可规定关联对象是否必选、允许类型和数量。
- 提交时保存对象标识和必要快照，避免对象改名影响历史解释。
- 统计方案可将允许的关联对象作为维度。

#### FR-LINK-002 CI 层级范围选择器

CI 字段应复用 CMDB 的三级目录结构，支持在一个选择器中混合多选：

```text
模型组：数据库
  ├─ 模型：MySQL
  │    ├─ CI：mysql-prod-01
  │    ├─ CI：mysql-prod-02
  │    └─ CI：mysql-test-01
  ├─ 模型：PostgreSQL
  └─ 模型：Redis
```

用户可以选择：

- 一个或多个模型组，例如数据库组、中间件组。
- 模型组中的一个或多个模型，例如数据库组下的 MySQL、PostgreSQL。
- 一个或多个具体 CI 实例。
- 模型组、模型和具体 CI 的混合组合。

选择器应支持：

- 按模型组逐级展开模型和实例。
- 按模型名称、CI 名称、编码和关键属性搜索。
- 按 CI 状态、所属组、负责人等授权属性筛选。
- 显示模型组、模型下当前可访问的 CI 数量。
- 大数据量下服务端分页和按需加载，不能一次加载全部实例。
- 已选模型组或模型以范围标签展示，不将大量 CI 全部展开为标签。
- 自动去重：选择“数据库组”后再选择“MySQL”或其中单个 CI，不得重复计数；界面应提示其已被上级范围覆盖。

#### FR-LINK-003 CI 字段使用模式

任务模板创建者可以为 CI 字段选择以下模式：

1. **固定关联范围**：创建者选择模型组、模型或具体 CI，任务自动关联该范围内的 CI。例如“巡检数据库组全部 CI”。
2. **限定范围内选择**：创建者先限定可选范围，执行人填写时再从范围内多选具体 CI。例如只允许从“数据库组 / MySQL”中选择本次巡检的实例。
3. **自由选择实例**：执行人在其有权查看的全部 CMDB 实例中选择一个或多个具体 CI。
4. **范围选择**：允许执行人直接选择模型组、模型或实例，适用于影响范围申报等场景。

每种模式均可配置：

- 单选或多选。
- 最少和最多选择数量。
- 是否允许选择整个模型组。
- 是否允许选择整个模型。
- 是否只允许选择具体实例。
- 是否允许选择停用或异常状态 CI。
- 是否允许任务创建者预填，执行人补充或修改。

#### FR-LINK-004 CI 范围解析与历史快照

系统必须同时保存“选择条件”和“实际命中快照”：

- 选择条件记录用户选择的模型组编码、模型编码和具体 CI ID。
- 实际命中快照记录解析时命中的 CI ID、名称、模型、模型组和状态等必要历史信息。
- 同一 CI 被多个已选范围覆盖时，实际命中结果只保留一份。
- 一次性任务在任务发布或正式提交时按使用模式生成快照。
- 周期计划保留动态范围条件，并在每次生成任务时重新查询 CMDB；后续新增的 MySQL 实例可以进入未来任务。
- 已生成任务、已提交版本和历史统计使用当时快照，不因新增、删除、改名或移动模型组而变化。
- 创建者可在发布计划前预览当前将命中的 CI 数量和明细；范围过大时必须提示并二次确认。

示例：

```text
计划范围：数据库组 / MySQL

2026-07-22 生成任务时命中：12 个 CI
2026-07-29 新增 2 个 MySQL CI
2026-07-30 生成的新任务命中：14 个 CI

2026-07-22 的历史任务仍保持 12 个 CI，不回写为 14 个。
```

#### FR-LINK-005 CI 权限边界

- CI 目录、搜索和实例明细必须复用现有 CMDB 租户隔离及读取权限。
- 选择整个模型组或模型不会自动授予其下 CI 的查看权限。
- “限定范围内选择”只展示执行人同时具备访问权限的 CI。
- 固定关联范围包含执行人无权查看的敏感 CI 时，系统应在任务发布或分配时提示创建者，不得通过任务详情旁路泄露。
- 统计和导出按查看人的任务权限与 CMDB 权限交集过滤。
- CI 下载、下钻和关联资源访问继续由 CMDB 对应资源权限控制。

### 11.4 任务计划与调度

#### FR-PLAN-001 时间规则

计划支持：

- 一次性。
- 每日、每周、每月、每季度、半年、每年。
- 工作日和节假日相对规则。
- 高级 Cron 配置，但默认通过可视化配置生成。
- 开始日期、结束日期、永久有效和暂停区间。
- 提前生成天数和截止时间计算规则。

#### FR-PLAN-002 节假日策略

周期落在非工作日时，可配置：

- 仍然生成。
- 跳过本次。
- 提前到上一个工作日。
- 顺延到下一个工作日。

#### FR-PLAN-003 分配规则

支持：

- 指定一个或多个人员。
- 指定用户组全部成员。
- 指定用户组负责人。
- 按值班表确定执行人。
- 每人生成独立任务。
- 全组生成一份协作任务。
- 按组分别生成任务。

计划生成任务时必须保存执行人和组织归属快照。人员后续调组不改变历史统计归属。

#### FR-PLAN-004 预览与幂等

- 发布计划前展示未来若干次任务、执行人和截止时间。
- 周期生成应具备业务幂等键，重复调度不得产生重复任务。
- 计划规则修改只影响尚未生成的未来任务，除非创建者明确选择批量更新。
- 批量影响已生成任务时必须展示影响范围并二次确认。

### 11.5 任务实例与协作

#### FR-TASK-001 任务详情

任务详情展示：

- 标题、说明、计划时间、截止时间、优先级和状态。
- 负责人、协作人、创建者和抄送人。
- 表单内容、附件要求和关联对象。
- 当前审批状态、审批进度和历史意见。
- 任务动态日志和通知记录。
- 权限允许的快捷操作。

#### FR-TASK-002 草稿与自动保存

- 表单填写支持自动保存草稿。
- 草稿不进入正式统计。
- 多人协作任务需显示最近编辑人和更新时间。
- 首期多人协作可采用字段级最后写入覆盖，并提示并发更新；复杂实时协同后续评估。

#### FR-TASK-003 提交校验

正式提交前，系统必须校验：

- 必填字段。
- 字段格式和业务范围。
- 表格行和列规则。
- 附件数量、类型和大小。
- 关联对象要求。
- 计算字段有效性。

前端校验用于体验，后端必须执行同等或更严格校验。

#### FR-TASK-004 提交版本

每次正式提交形成不可变版本，至少包含：

- 任务和模板版本。
- 表单数据快照。
- 附件清单快照。
- 关联对象快照。
- 执行人和组织快照。
- 提交人、提交时间和版本号。
- 计算字段后端结果。

#### FR-TASK-005 执行状态

任务执行状态建议定义为：

```text
未开始 → 进行中 → 已提交 → 已完成
                    ↓
                  待修改 → 已提交

任意未终态 → 已取消
异常处理   → 异常关闭
```

逾期建议作为独立时间标记，而不是替换业务状态。例如任务可以同时是“进行中 + 已逾期”。

### 11.6 审批方案与审批闭环

#### FR-APP-001 审批模式

任务模板或任务计划可以选择：

- 无需审批。
- 指定人员审批。
- 指定组内任一人审批。
- 多人会签。
- 顺序多级审批。
- 使用已发布的高级流程定义。

计划绑定具体审批方案版本。任务生成时固化审批方案版本，不能按全租户单一 `businessType` 隐式切换。

#### FR-APP-002 审批动作

审批节点按方案配置允许的动作：

- 通过。
- 退回执行人修改。
- 退回上一个审批节点。
- 驳回并终止。
- 转交或加签，作为后续增强能力。

#### FR-APP-003 退回理由

退回修改时审批理由必须填写。审批人还可以：

- 标记一个或多个问题字段。
- 对具体附件填写意见。
- 标记问题级别。
- 上传补充说明附件。

执行人收到退回后必须看到：

- 审批节点和审批人。
- 退回时间。
- 退回理由。
- 问题字段和附件意见。
- 上次提交内容。
- 修改并重新提交入口。

#### FR-APP-004 审批轮次和记录

- 每次重新提交产生新的审批轮次。
- 每个审批节点形成独立审批记录。
- 旧提交版本、拒绝理由和审批记录不可覆盖或删除。
- 重新提交后支持查看字段差异、附件差异和审批意见处理情况。
- 最终审批结果需要回写任务状态，并发送通知。

#### FR-APP-005 审批状态

审批状态独立于任务执行状态，至少包括：

```text
无需审批
未发起
审批中
已通过
已退回
已终止
审批异常
```

### 11.7 提醒与升级

#### FR-NOTIFY-001 提醒阶段

计划可以配置：

- 任务生成通知。
- 开始前提醒。
- 截止前多次提醒。
- 到期提醒。
- 逾期提醒。
- 审批待办提醒。
- 退回修改通知。
- 审批通过或终止通知。

#### FR-NOTIFY-002 接收人与渠道

- 接收人可包括负责人、协作人、创建者、抄送人、审批人和升级对象。
- 支持站内通知；邮件、企业即时通信等渠道作为可插拔扩展。
- 同一任务、阶段、用户和渠道需要保证通知幂等。

#### FR-NOTIFY-003 逾期升级

- 可配置逾期若干时间后通知组负责人或指定人员。
- 支持多级升级策略。
- 升级只改变通知和风险标记，不自动修改表单数据或审批结果。

### 11.8 我的工作

#### FR-WORK-001 聚合视图

“我的工作”至少包括：

- 待执行：我负责或参与的未完成业务任务。
- 待审批：我当前可处理的审批节点。
- 我发起的：我创建的任务及进度。
- 抄送我的：我被授权只读关注的事项。
- 已完成：我参与过且已经完成的任务或审批。

#### FR-WORK-002 筛选和排序

支持按以下条件筛选：

- 任务或审批类型。
- 模板、计划和任务分类。
- 状态、优先级和逾期状态。
- 时间范围、组和创建者。
- 是否需要我处理。

默认优先展示已逾期、即将到期和高优先级事项。

### 11.9 运维日历

#### FR-CAL-001 日历数据源

- 日历读取统一任务实例，不维护独立任务数据。
- 保持现有单页面多视图交互，不为月、周、列表视图拆分子路由或独立页面。
- 月、周和列表视图通过页面内控件切换，并共享日期范围、任务范围、类型、状态等筛选条件。
- 视图切换后保留用户筛选上下文；返回日历时优先恢复用户最近使用的视图。
- 支持我的、本组和授权范围内的任务。
- 排班等非任务时间对象可作为独立图层展示，但需明确类型。

#### FR-CAL-002 快捷操作

- 点击日历项进入统一任务详情。
- 支持从日期快捷创建一次性任务。
- 支持按模板、状态、类型、人员和组筛选。
- 日历只提供轻量快捷操作，复杂填写和审批进入详情页完成。

### 11.10 日报、周报和季报

#### FR-REPORT-001 日报作为内置任务模板

系统提供“工作日报”内置模板，默认字段包括：

- 今日完成事项。
- 遇到的问题。
- 明日计划。
- 工作时长。
- 关联 CI。
- 可选附件。

默认计划按工作日为每位适用人员分别生成任务，可配置审批方案。

#### FR-REPORT-002 不同周期独立定义

- 日报、周报、月报、季报可以使用完全不同的表单。
- 不要求它们具备相同字段或维度。
- 周报和季报可以包含本周期原生字段，也可以引用低周期数据的自动汇总结果。
- 自动汇总字段默认只读，避免人工修改系统计算结果。

#### FR-REPORT-003 三类汇总值

报表中必须区分：

1. 原始事实值：来自底层任务提交。
2. 系统汇总值：由原始数据计算产生。
3. 人工上报值：由执行人在当前周期填写。

当人工上报值与系统汇总值同时存在时，应分别展示差异和差异说明，不得直接覆盖。

### 11.11 自定义统计

#### FR-STAT-001 统计方案

统计方案包含：

- 名称、描述、所有者和共享范围。
- 一个或多个任务模板数据源。
- 时间字段和统计周期。
- 有效数据范围。
- 指标、维度、筛选和排序。
- 组件类型和展示配置。
- 下钻规则和导出权限。

#### FR-STAT-002 有效数据范围

统计创建者可选择：

- 仅当前有效提交版本。
- 仅审批通过的数据。
- 包含无需审批且已完成的数据。
- 是否包含审批中、被退回或已取消任务。
- 按任务业务日期、提交时间或审批通过时间统计。

系统默认推荐“当前有效版本 + 已完成或审批通过”。被退回的历史版本保留审计，但不重复进入正式统计。

#### FR-STAT-003 字段分析角色

将字段加入统计方案时，创建者必须指定其用途：

- 指标：需要计算的值。
- 维度：用于分组和分类。
- 筛选条件：用于限定数据范围。
- 明细内容：用于列表和下钻。
- 附件证据：用于文件或图片展示。

同一字段可以承担多个允许的角色，例如“风险等级”既可作为维度，也可作为筛选条件。

#### FR-STAT-004 数字字段

数字字段支持：

- 合计、平均、最大、最小、中位数和记录数。
- 去重计数。
- 加权平均。
- 同比、环比、目标值和完成率。
- 受控公式指标。

每个数字指标需要声明单位、精度、空值处理、默认聚合和数值方向。

#### FR-STAT-005 聚合性质

指标必须声明聚合性质：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 可累加 | 可跨时间和组织直接求和 | 巡检次数、故障数量、工作时长 |
| 半累加 | 只允许部分维度求和 | 库存可按组求和，跨日期取期末值 |
| 不可累加 | 不能直接对结果再次求和或平均 | 完成率、平均响应时间、在线率 |
| 去重指标 | 需要按业务键去重 | 影响设备数、参与人数 |
| 快照指标 | 取期初、期末或最近值 | 期末风险数量 |
| 公式指标 | 由基础指标计算 | 关闭率、通过率、覆盖率 |

平均值和百分比应优先保存或引用分子、分母。例如跨日平均巡检耗时使用“总耗时 ÷ 总巡检次数”，不能直接平均每日平均值。

#### FR-STAT-006 选项和布尔字段

- 单选支持选项数量、占比和趋势。
- 多选按每个选项分别计数，可配置一条记录多次归类。
- 布尔和检查项支持完成数、通过率、异常率和缺失率。
- 已停用历史选项仍保留历史标签和统计含义。

#### FR-STAT-007 文字字段

文字字段首期支持：

- 原文列表。
- 全文搜索。
- 按预设标签或分类汇总。
- 按任务、人员、组和时间过滤。
- 导出和下钻。

后续可扩展：关键词排行、相似问题聚类和 AI 摘要。AI 结果必须标记来源，不能直接替代正式分类字段。

#### FR-STAT-008 表格字段

- 表格可按行拆分为统计明细。
- 数字列可聚合。
- 选项列可分类。
- 行数可作为指标。
- 表格行必须保留其所属任务、提交版本和父记录上下文。

#### FR-STAT-009 附件字段

附件支持：

- 附件总数、任务覆盖率和缺失率。
- 文件类型、附件分类和文件大小分布。
- 文件列表、图片墙和任务证据列表。
- 点击附件回到原任务或提交版本。

首期仅统计附件元数据，不默认解析附件正文。后续可在权限允许时扩展 PDF/Excel 解析、OCR 和内容检索。

#### FR-STAT-010 时间和组织维度

支持：

- 按日、周、月、季度、年度和自定义时间范围。
- 按执行人、提交人、创建者、审批人和组织分组。
- 按任务执行时的组织快照统计历史数据。
- 对跨组人员保留当时归属，不因当前组织调整重算历史。

#### FR-STAT-011 自定义字段维度

- 单选、多选、人员、组、CI 模型组、CI 模型、具体 CI、其他关联对象和部分稳定文本标签可以配置为维度。
- 指标声明自己支持的维度。
- 数据未采集某维度时显示“无该维度数据”，不得推测补齐。

#### FR-STAT-012 跨模板字段映射

统计方案可以将不同模板字段映射到统一指标，例如：

```text
每日巡检.巡检次数 ─┐
专项巡检.完成数量 ─┼→ 统一指标：巡检次数
人工周报.本周次数 ─┘
```

映射时必须检查：

- 数据类型兼容。
- 单位一致或配置明确换算。
- 聚合性质一致。
- 时间口径一致。
- 权威来源明确。

#### FR-STAT-013 权威来源与防重复

同一指标同时出现在日报、周报和季报时，统计方案必须指定：

- 原始事实来源。
- 系统汇总来源。
- 人工核对来源。
- 正式看板采用的权威来源。

默认不得将日报事实值和周报汇总值再次相加。

### 11.12 看板与展示

#### FR-DASH-001 展示组件

首期建议支持：

| 组件 | 适用场景 |
| --- | --- |
| KPI 卡片 | 总数、平均值、完成率、异常数 |
| 折线图 | 时间趋势、同比和环比 |
| 柱状图 | 组织、人员、类别对比 |
| 堆叠图 | 多状态或多类别构成 |
| 饼图/环图 | 少量类别占比 |
| 明细表 | 复杂数据、排序、分页和导出 |
| 交叉表 | 时间与组织、类别的二维分析 |
| 日历热力图 | 每日任务量、异常量、提交情况 |
| 文字列表 | 问题描述、工作总结和备注 |
| 标签排行 | 高频分类和选项 |
| 附件列表 | 文件证据和下载入口 |
| 图片墙 | 巡检照片和整改证明 |

#### FR-DASH-002 组件配置

每个组件保存独立的：

- 数据源。
- 指标和维度。
- 时间范围。
- 筛选条件。
- 排序和 Top N。
- 图例、单位和空值展示。
- 下钻目标。

#### FR-DASH-003 看板能力

- 支持拖拽布局和调整组件大小。
- 支持个人看板、组看板和租户共享看板。
- 支持保存筛选条件。
- 支持点击图表下钻到任务、提交版本、字段明细和附件。
- 支持 Excel/CSV 导出；PDF 和定时发送作为后续能力。
- 看板需要展示统计口径说明和最后更新时间。

### 11.13 查询、导出与审计

#### FR-QUERY-001 全局查询

支持按标题、模板、人员、组、状态、日期、标签和结构化字段查询任务。敏感字段不进入无权限全文检索结果。

#### FR-EXPORT-001 数据导出

- 导出遵循当前用户权限和字段可见性。
- 导出文件包含统计口径、时间范围和生成时间。
- 附件默认不打包导出；批量附件导出需独立权限和审计。

#### FR-AUDIT-001 审计事件

至少记录：

- 模板创建、发布、停用和版本变更。
- 计划创建、启停、规则修改和批量影响。
- 任务生成、转交、取消和异常关闭。
- 草稿关键操作、正式提交和重新提交。
- 附件上传、替换、删除、下载和导出。
- 审批认领、通过、退回、终止和意见。
- 统计方案创建、修改、共享和导出。
- 权限及敏感字段配置变更。

## 12. 统计示例

### 12.1 每日巡检

模板字段：

- 巡检设备数：数字，可累加。
- 正常设备数：数字，可累加。
- 发现问题数：数字，可累加。
- 巡检耗时：数字，单位分钟，可累加。
- 巡检通过率：公式字段，正常设备数 ÷ 巡检设备数。
- 风险等级：单选，可作为维度。
- 问题说明：多行文本，作为明细内容。
- 巡检照片：图片附件，作为附件证据。
- 关联 CI：关联对象，可作为维度。

可形成：

- 最近 30 天巡检次数折线图。
- 各组问题数量柱状图。
- 风险等级占比图。
- 巡检通过率 KPI。
- 问题说明列表。
- 巡检图片墙。

### 12.2 周报引用日报数据

周报可以包含：

- 本周巡检总次数：从日报自动汇总，只读。
- 本周问题总数：从日报自动汇总，只读。
- 本周重点工作：周报原生文字字段。
- 下周计划：周报原生文字字段。
- 人工确认巡检次数：人工上报值。
- 差异说明：人工值与系统值不一致时必填。

系统展示：

```text
系统计算巡检次数：126
人工确认巡检次数：123
差异：-3
差异说明：3 次测试巡检不计入正式口径
```

### 12.3 季报独立维度

季报可以采集日报不存在的字段：

- 重大风险数量。
- 风险等级。
- 预算执行率。
- 季度改进计划。

这些字段独立统计，不要求映射到日报。只有业务含义一致且满足类型、单位和口径要求的字段才映射为共享指标。

## 13. 自动化扩展能力

以下能力建议在核心任务与统计稳定后逐步扩展：

### 13.1 阈值联动

创建者可以配置：

```text
当“严重问题数 > 0”时：
  自动创建整改任务
  负责人取原任务所属组负责人
  截止时间为 24 小时后
```

### 13.2 任务链路

- 巡检任务发现问题后创建整改任务。
- 整改完成后创建复查任务。
- 复查通过后关闭问题链路。
- 子任务继承来源任务、字段摘要、附件和关联对象引用。

### 13.3 目标和预警

- 为组或人员设置周、月、季度目标。
- 展示完成率和目标差距。
- 连续未提交、数值突增、趋势下降时触发预警。

### 13.4 智能分析

- 对文字字段生成周期摘要。
- 对问题文本进行辅助标签和聚类。
- 对指标异常生成解释建议。
- 对附件进行 OCR 或结构化提取。

智能结果只作为辅助信息，不直接修改正式指标、审批结果或任务状态。

## 14. 非功能要求

### 14.1 性能

- 我的工作首屏常规查询建议在 2 秒内返回。
- 普通任务详情建议在 2 秒内返回，附件内容不要求同步加载。
- 常用看板在典型数据量下建议在 3 秒内完成首屏渲染。
- 大时间范围统计采用异步查询、缓存或预聚合，不阻塞普通任务接口。
- 周期任务批量生成需分批执行，保证幂等和可重试。

### 14.2 可用性

- 草稿自动保存失败时明确提示，不能制造已保存假象。
- 调度、通知、指标提取和流程回调均需可重试和可巡检。
- 审批完成与业务状态回写需要幂等。
- 统计结果显示数据更新时间和是否来自缓存。

### 14.3 安全

- 所有查询强制租户隔离。
- 组织范围、任务参与关系和资源权限共同决定可见性。
- 附件使用受控访问地址，不暴露永久公共链接。
- 公式和条件使用受控表达式，不执行任意代码。
- 导出、批量下载和共享看板记录审计。
- 敏感字段支持脱敏、禁止统计和禁止导出。

### 14.4 数据一致性

- 模板版本、审批方案版本和任务实例关系不可丢失。
- 提交版本不可覆盖。
- 指标事实必须能追溯到任务、提交版本和字段。
- 重新提交后旧指标事实失效但不删除，正式统计只读取当前有效版本。
- 组织、人员名称和关联对象保存必要历史快照。

### 14.5 可扩展性

- 字段类型通过注册机制扩展。
- 业务关联对象通过适配器扩展。
- 审批方案通过流程模板扩展。
- 统计组件通过组件注册扩展。
- 通知渠道通过通道适配器扩展。

## 16. 分阶段范围

### 16.1 阶段一：统一任务基础

- 内置日报模板、工作日计划和日报快捷筛选。
- 删除旧日报页面、接口、服务、审批适配器、配置和数据表。

### 16.3 阶段三：自定义统计与看板

### 16.4 阶段四：跨周期汇总与自动化

范围：

- 日报到周报、月报和季报的引用汇总。

- 系统汇总值、人工上报值和差异说明。

- 评估 AI 摘要、分类和附件内容提取。

## 17. 现有模块切换与清理策略

### 17.1 前提与原则

本项目采用“运行时硬切换 + 数据库增量迁移”：不做新旧模型双写双读，但必须保护现有数据库、V1-V79 migration 历史和其他正式业务模块数据。旧日报、旧运维任务及其专属数据在消费者切换后通过定向 migration 物理删除；用户、RBAC、CMDB、设备、Wiki、共享文件、通知等其他正式业务模块对象不属于本项目删除范围。

必须遵循：

- 不做新旧任务模型双写。
- 不做旧日报和新任务双读。
- 不保留长期兼容 API、兼容页面、兼容 DTO 或兼容数据视图。
- 不为现有日报和运维任务数据编写保留性迁移；它们属于允许定向删除的目标域数据。
- 通过明确、可验证的 `ALTER / DELETE / DROP` 增量 migration 收口旧 schema，不改写历史 migration。
- 既有数据库正常升级；全新安装从 V1 执行到最新版本，两条路径达到同一终态。
- 功能切换与旧代码删除在同一建设计划内完成，不能把清理工作留作无截止日期的技术债。

本原则只适用于当前未上线数据。新平台正式产生任务后，模板版本、提交版本、审批记录和统计血缘必须永久可追溯。

### 17.2 运维日历的最终处理

运维日历保留，因为它是有明确价值的时间视图，但其任务领域能力迁入统一任务中心。

保留：

- `/ops-calendar` 单页面入口。
- 月、周、列表视图的页面内切换。
- 日期导航、任务筛选、状态标记和任务详情快捷入口。
- 排班和节假日能力；建议收敛为一个“日历设置”页面或设置区，而不是散落多个同级入口。
- 当前周期计算、幂等生成、提醒、排班和节假日逻辑中可复用的实现经验。

迁入统一任务域：

- 周期规则改为“任务计划”。
- 运维模板改为“任务模板”。
- 运维任务和检查项改为“任务实例 + 表单定义 + 提交版本”。
- 运维任务统计改为“自定义统计方案和看板”。
- 素材归集改为任务附件和附件统计组件。

删除：

- 旧运维任务、规则、模板、统计和素材页面。
- `/api/ops-calendar/tasks`、`/api/ops-calendar/rules`、`/api/ops-calendar/templates`、`/api/ops-calendar/stats`、`/api/ops-calendar/report-materials` 等旧业务接口。
- 旧 `OpsScheduleTask`、`OpsScheduleRule`、`OpsScheduleTemplate`、检查项、参与人、任务链接和相关 Mapper/Service/DTO。
- `ops_schedule_task`、`ops_schedule_rule`、`ops_schedule_template`、`ops_schedule_checklist_item` 等被新任务 schema 替代的表。

运维日历最终只消费统一日历查询接口，不拥有第二套任务状态机。

### 17.3 日报的最终处理

日报不再作为独立业务模块存在，而是系统内置的“工作日报”任务模板。

新形态：

- 使用通用任务模板定义完成事项、问题、明日计划、工时、CI 和附件字段。
- 使用任务计划在工作日为每位适用人员生成任务。
- 使用通用提交版本保存日报内容。
- 使用任务级审批方案处理日报审批。
- 使用自定义统计方案形成日报、周报和人员/组统计。
- 可提供“日报”快捷筛选或首页快捷卡片，但该入口必须复用统一任务页面，不建设独立 CRUD 页面。

删除：

- `/daily`、`/daily/new`、`/daily/[id]` 页面及日报专属前端组件。
- `/api/daily-reports` 全部接口。
- `DailyReportController`、`DailyReportService`、`DailyReportMapper`、实体和 DTO。
- `DailyReportWorkflowAdapter`、`DailyReportApprovalListener`、`DailyReportBindingSeeder` 等日报专属流程代码。
- 日报专属提醒 Scheduler/Handler、通知目标分支和系统配置项。
- `daily_report`、`daily_report_approval` 等日报专属数据表。
- `daily_report:*` 权限，改由任务、审批和统计权限控制。
- 日报专属导出服务，改为统一统计和提交数据导出。

CMDB 中的“相关日报”改为“相关任务/报告”，通过统一任务与 CI 关联查询，不再直接依赖日报表。

### 17.4 流程中心的最终处理

流程中心不删除，但重新定位为“审批引擎和流程管理”，不再把审批节点命名成业务任务。

保留：

- Flowable 引擎及其运行时数据结构。
- `WorkflowRuntimeFacade`、流程事件和通用业务适配协议。
- 审批方案、流程模板、流程定义版本、流程实例、流程设计和流程统计。
- Wiki、变更文档等仍需要专业业务流程的适配器。
- 审批候选人、权限复核、流程历史和审计能力。

调整：

- 新增统一任务业务适配器，业务类型面向任务提交，而不是为日报等模板分别创建适配器。
- 任务计划绑定具体审批方案版本；任务生成后固化该版本。
- 用户审批入口统一到“我的工作 → 待审批”。
- 审批 API 使用单一正式契约；建议收敛为 `/api/approvals` 或统一工作项 API，最终名称在 SPEC 中确定。
- 流程管理 API 与用户审批 API 分离，避免一个大 Controller 同时承担两类职责。

删除：

- `/workflow/todo` 和 `/workflow/tasks` 两个重复用户页面。
- `/api/workflow/tasks/my`、`/api/workflow/tasks/group`、`/api/workflow/approve` 旧接口。
- `/api/workflow/center/tasks/*` 与旧接口重复的待办和完成接口。
- 仅为旧日报兼容存在的 business key 映射、流程绑定和审批摘要代码。
- 旧 `TaskVO` 等只服务于兼容接口的 DTO。

流程实例、流程设计和管理页面继续存在，但普通执行人主要通过“我的工作”使用审批能力。

### 17.5 数据库 schema 处理

本次允许重新设计目标域 schema，但必须通过既有 Flyway 链上的增量 migration 实施：

- 以新的任务、表单、计划、提交、审批、指标和看板模型作为唯一正式 schema。
- 删除日报和旧运维任务相关建表语句、外键、索引、触发器、种子和权限种子。
- 保留并整理仍有价值的 Flowable、排班、节假日、通知、CMDB 等 schema。
- 保留 V1-V79 历史，V80+ 新增统一任务对象，消费者切换后再用新版本定向删除旧对象。
- 既有开发、测试和演示环境正常升级，不清库、不整体替换 schema。
- 初始化数据只包含新任务内置模板、审批方案、权限和必要演示数据。
- 对旧任务域、关联共享目标行和明确一次性切换模型执行消费者审计；其他正式业务模块的表、列、约束、函数和配置保持不变。

具体表名、索引、JSONB/事实表拆分和 Flyway 基线方式在技术 SPEC 中确定。

### 17.6 代码切换顺序

建议按以下顺序实施，但不对用户暴露长期兼容阶段：

1. 建立新任务、表单、提交、审批绑定和统计 schema。
2. 建立新任务 API 和“我的工作”页面。
3. 将运维日历主页面切换到统一日历查询接口。
4. 初始化日报模板和工作日计划，验证日报完整链路。
5. 将流程审批入口切换到“我的工作 → 待审批”。
6. 将 CMDB、通知、首页和报表引用切换到新任务对象。
7. 物理删除旧日报、旧运维任务和重复流程待办的页面、接口、代码、权限及 schema。
8. 分别执行 V79 增量升级、V1 全新安装和全量零残留验证。

### 17.7 回退方式

回退不依赖旧运行时兼容层：

- 代码问题通过 Git 版本回退。
- schema 问题通过升级前备份恢复；已执行 migration 不改写，前向修复使用下一递增版本。
- 不为了运行时回退保留旧 Controller、旧页面、旧表或双写逻辑。

### 17.8 变更文档能力复用

- 复用其动态字段、表格数据和后端校验经验。
- 公共字段协议和渲染组件应抽取为通用能力。
- 任务平台不直接依赖变更文档表结构，避免模块耦合。

## 18. 验收标准

### AC-001 高度定制任务

管理员可以创建一个包含文本、数字、单选、表格和必传附件的模板，发布后由另一名用户据此创建一次性任务并成功提交。

### AC-002 周期生成

管理员可以配置每个工作日为某组每位成员分别生成任务；系统预览正确，重复调度不产生重复任务。

### AC-003 模板版本

模板发布新版本后，历史任务仍按旧版本正确展示、校验和导出，新任务可以明确选择新版本。

### AC-004 审批退回

审批人退回时必须填写理由；执行人能看到理由、问题字段和附件意见，修改后形成新提交版本和新审批轮次。

### AC-005 日历定位

运维日历保持单页面结构，可在月、周、列表视图之间切换并保留筛选上下文；各视图显示统一任务实例并进入同一个任务详情，不产生第二套任务数据。

### AC-006 日报模板

工作日报可通过周期任务生成，完整覆盖现有日报字段、审批和关联 CI 能力，并且用户不需要双重填报。

### AC-007 数字统计

统计创建者可以选择一个数字字段，按自定义时间范围和组展示合计、平均值和趋势，并下钻到原任务。

### AC-008 多类型统计

同一看板可以展示数字 KPI、选项分类图、文字明细列表、附件数量和图片墙，且所有内容遵循原任务权限。

### AC-009 跨周期口径

周报可以引用日报自动汇总值，同时保存人工上报值和差异说明；正式统计不会将日报与周报汇总值重复相加。

### AC-010 历史组织统计

人员调组后，历史任务仍按任务执行时的组织快照统计，新任务按新组织统计。

### AC-011 审计追溯

任意正式统计值可以追溯到统计方案、指标定义、任务、提交版本和原始字段。

### AC-012 数据权限

无权查看某任务或敏感字段的用户，无法通过统计、下钻、导出或附件链接获取该数据。

### AC-013 CI 层级选择

创建者可以在同一 CI 选择器中混合选择“数据库模型组”“MySQL 模型”和具体 CI，系统正确去重并预览实际命中范围；周期计划新增 MySQL CI 后只影响未来生成任务，历史任务和提交快照保持不变。

### AC-014 CI 限定范围

模板创建者可以将 CI 字段限定为“数据库模型组 / MySQL 模型”，执行人只能从自己有权查看且属于该范围的具体 CI 中多选；统计看板可以分别按模型组、模型和具体 CI 下钻。

### AC-015 旧实现清理

最终构建产物和数据库基线中不再存在旧日报页面与 `/api/daily-reports`、旧 `/api/ops-calendar/tasks|rules|templates|stats|report-materials`、重复 workflow 待办与审批接口，以及仅服务这些接口的 Controller、Service、DTO、权限种子和数据表；运维日历、我的工作和流程管理分别只调用唯一正式 API。

## 19. 风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 过度自由导致模板难以维护 | 模板质量下降 | 模板版本、预览、发布审核、内置示例 |
| 表单 JSON 难以高效统计 | 看板性能差 | 指标事实提取、索引和预聚合 |
| 日报与周报重复统计 | 管理数据失真 | 权威来源、来源类型和血缘追踪 |
| 模板更新破坏历史任务 | 审计不可复现 | 发布版本不可变，任务绑定具体版本 |
| 审批状态与任务状态混乱 | 流转错误 | 双状态模型和明确状态转换规则 |
| 附件统计造成越权 | 泄露敏感材料 | 权限继承、字段级控制、下载审计 |
| 条件和公式被滥用 | 安全或稳定性风险 | 受控表达式、复杂度限制、服务端校验 |
| 周期任务批量生成压力大 | 重复任务或延迟 | 幂等键、分批调度、重试和巡检 |
| 历史组织变更导致口径漂移 | 历史报表变化 | 保存组织快照，明确当前/历史口径 |
| AI 汇总被当作事实 | 决策失真 | AI 结果标识、人工确认、不覆盖正式指标 |

## 20. 与既有规划的关系

- 本 PRD 延续现有流程中心的统一运行门面、流程模板、业务适配器和版本绑定方向。
- 本 PRD 将此前“运维日历交付物验收不接入流程中心”的边界调整为：普通轻量任务可以无审批完成；当任务模板明确配置审批时，通过通用任务适配器接入流程中心。
- 本 PRD 保留运维日历的展示价值，但将任务数据所有权收敛到统一任务域。
- 本 PRD 将日报重新定义为内置周期任务模板，在新模型中重新提供审批和 CI 关联能力，不保留旧日报实现。
- 本 PRD 复用变更文档动态表单经验，但不把任务平台耦合到变更文档业务表。
