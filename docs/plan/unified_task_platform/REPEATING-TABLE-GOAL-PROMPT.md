## 2. Goal 定义

### 2.1 目标

在不改变现有任务模板、任务填写、审批、提醒、分配和统计主体能力的前提下，为任务模板增加“自定义表格（可重复明细表）”字段。它用于周报、巡检记录和工作明细等“列由模板固定、行数由执行人决定”的场景。

该能力是现有动态表单字段体系的一种字段类型，不是一套独立的表单、附件或报表系统。

### 2.2 不在范围内

- 不重新实施或回退已完成的统一任务平台工作包。
- 不修改 V1–V79 migration，不重建数据库，不执行全库清理。
- 不改变已有任务、审批、提醒、分配、日历或普通字段的 API 语义。
- 不在首期实现表格行级审批意见、跨模板行级数据仓库或全新的“按行展开”报表页面。
- 不提交、不推送、不重建前后端容器，除非用户明确要求。

## 3. 产品合同

### 3.1 表格字段配置

模板设计者可新增“自定义表格”字段，并配置：

1. 表格名称、说明、整体必填、默认行数、最少行数、最多行数。
2. 固定列：新增、删除、排序；每列必须有稳定且唯一的编码、中文表头、类型和必填规则。
3. 首期列类型：`auto_number`、`text`、`textarea`、`date`、`datetime`、`number`、`single_select`、`file`、`image`。
4. 自增序号列：只读；可配置起始值和步长；增删行后自动重排，服务端不得信任客户端传入的序号。
5. 数字列：最小值、最大值、小数位，以及页面内汇总方式（无、合计、平均值、最小值、最大值）。
6. 下拉列：受控选项配置。
7. 文件、图片列：数量与大小限制，并沿用既有附件安全、权限和冻结语义。
8. 非自增列可选择是否提供给任务统计；统计列名称必须使用中文表头。

已有字段体系中的人员、用户组、公式等类型仅在可以安全复用现有运行时、权限与统计语义时纳入；否则明确不纳入首期，不创建半成品实现。

### 3.2 填写、提交与回显

执行人可以新增、复制、删除行，受最少/最多行限制。列结构只能由模板设计者决定。

- 每行有稳定内部行标识；删除行后，该行的行内附件也必须一并解除草稿关联。
- 行内附件按“表格字段 + 行标识 + 列编码”唯一绑定，不能与其它行或顶层附件混淆。
- 暂存、校验、提交、附件冻结、任务详情、提交历史和审批查看必须保留完整表格结构与数据。
- 历史任务和历史提交按照其模板版本/提交快照只读回显；已发布模板版本保持不可变。
- 校验错误定位到具体表格、行和列；错误路径应可供前端准确高亮。

### 3.3 审批与统计

- 审批详情、附件下载权限和审批附件意见必须识别可见的行内附件。
- 当前审批意见模型保持“字段整体”粒度；表格行/列级意见是后续能力，不能临时修改 schema 伪造。
- 表格数字列按配置计算填写页汇总；默认统计聚合继承该汇总配置。
- 启用统计的表格列通过既有 `fieldKey + tableColumn` 查询契约接入，避免平行统计接口。
- 统计表、导出和分析不重复显示顶层“字段”列；展示使用中文列名。业务日期、提交时间等既有固定列规则保持不变。
- 本期数据结构必须为未来按行展开分析保留可追溯的 `fieldKey`、`subFieldKey`、`rowKey`，但不额外扩展为新报表模式。

## 4. 实施要求

1. 先检查 `git status --short`，把现有未提交修改视为用户资产，不能覆盖、重置或混入无关整理。
2. 先阅读现有模板字段注册、表单运行时、任务草稿/提交附件、任务详情/提交历史、审批详情、统计查询和相邻测试，再选择最小改动路径。
3. 修改任何函数、类或方法前，按根 `AGENTS.md` 运行 GitNexus upstream impact，记录直接调用者、受影响流程和风险。风险为 HIGH 或 CRITICAL 时，在编辑前向用户说明范围、缓解与原因。
4. 复用现有字段元数据、JSON 配置、校验框架、附件存储、版本快照和字段事实模型。除非证明现有模型无法满足不变量，否则不新增数据库表或迁移。
5. 后端是最终校验源：校验列配置、行数、行值、数值精度、下拉选项、附件限制和自增序号；不得仅在前端校验。
6. 前端设计器、填写页、任务详情、历史提交、审批抽屉和统计选择器必须使用一致的列定义及中文名称。
7. 更新用户使用说明，讲清楚配置列、维护行、附件绑定、数字汇总、统计入口与当前限制。
8. 不得以 TODO、空接口、mock 数据或未接入真实 API 的页面作为完成。

## 5. 推荐交付切片

按依赖顺序推进；每个切片完成后运行最小验证，避免最后集中排错：

1. **运行时与配置：** 注册字段类型，定义并校验表格与列配置，生成默认行和稳定行标识。
2. **草稿、提交与附件：** 接入草稿校验、提交冻结与行内附件清理/授权。
3. **设计与填写：** 实现模板列设计器、动态表格、增删复制行、附件与数字汇总。
4. **只读与审批：** 任务详情、历史提交和审批详情正确回显表格与行内附件。
5. **统计与说明：** 接入已选统计列、中文展示和使用文档。
6. **回归与收口：** 补齐高风险路径测试，运行质量门禁和 GitNexus 变更审查。

## 6. 验收与验证

只有全部满足才可标记 Goal `complete`：

- 可创建、发布含自定义表格的模板；配置的列、校验、自增序号、附件限制和数字汇总生效。
- 执行人可在限制内新增、复制、删除行；提交和暂存成功；错误准确定位到行列。
- 行内附件不会串行，删除行后草稿附件不遗留，提交后附件可按既有权限下载。
- 任务详情、提交历史和审批详情完整且按快照回显表格；审批可见性不泄露隐藏的行内附件。
- 启用统计的数字列可按既有统计入口选择，名称中文且不与顶层普通字段重复；普通模板和历史任务无回归。

5. 明确说明没有执行提交、推送或容器重建，除非用户已授权并确实执行。

不得在测试失败、文档缺失、关键审批路径未验证或变更范围未审查时标记 Goal 完成。
