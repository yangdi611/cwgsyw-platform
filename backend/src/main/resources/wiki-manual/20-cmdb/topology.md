# 关联与拓扑视图

关联描述配置项之间的关系，拓扑视图把这些关系可视化，帮助你理解基础设施的依赖结构。

## 建立关联

在某个 CI 实例的详情页 → 关联面板：

1. 点"新建关联"
2. 选择关联类型（语义）和目标 CI
3. 保存

建立前先确认“源 CI 到目标 CI”的方向和关系语义。例如“应用部署在主机上”应使用与部署语义一致的方向；方向错误会让影响分析和拓扑阅读产生误导。保存失败时，通常是模型间未定义该关系或违反了 1:1、1:n、n:n 基数约束，应联系 CMDB 管理员维护关联定义。

关联是**有方向**的（从源 CI 指向目标 CI），系统会校验该类型关联是否允许在这两个模型间建立，以及基数约束（1:1 / 1:n / n:n）。

## 关联类型（语义）

平台内置以下关联种类：

| 类型 | 含义 |
|------|------|
| 属于 | 包含/从属关系 |
| 运行 | 运行/被运行 |
| 连接 | 网络或逻辑连接 |
| 依赖 | A 依赖 B |
| 部署 | A 部署在 B 上 |

## 拓扑视图

进入某实例的拓扑全屏页：

- 以图形方式展示该 CI 及其关联的其他 CI
- 可选择**遍历深度**（1-5 层），看多远的关联
- 点击节点查看详情
- 支持按类型过滤、导出 PNG 图片

### 排查依赖的操作步骤

1. 在需要变更或故障的 CI 详情中进入拓扑。
2. 从 1 到 2 层开始查看，确认直接依赖；需要时逐步增加遍历深度，避免一次图中过多节点。
3. 使用关联类型过滤，区分部署、依赖、连接和从属关系。
4. 点击节点打开该 CI 详情，核对状态和责任信息。
5. 变更评审时导出当前视图或记录影响分析结果，再在变更文档中说明影响范围。

### 对比模式
可选择两个时间点，对比拓扑结构的变化（新增/删除/修改的节点和关联），用于排查"什么时候多了/少了一个依赖"。

## 影响分析

当某个 CI 要变更或下线时，影响分析帮你回答"动它会影响哪些其他系统"：

- 从目标 CI 出发，沿关联向外遍历
- 列出所有受影响的 CI

这是变更前评估风险的重要工具。需要 `cmdb_instance:impact` 权限。

## 2D 分组视图

对启用了 2D 视图的模型，可按某个属性分组，以网格方式展示实例，适合按机房、环境等维度俯瞰资源分布。

## 维护原则

- 关系应描述稳定的业务或技术事实，不要为一次临时操作建立长期依赖。
- 删除或调整关键关联前，先执行影响分析并通知关联 CI 的负责人。
- 拓扑历史对比展示 CMDB 数据变化，不自动证明真实网络或应用状态，仍需结合监控和现场确认。
