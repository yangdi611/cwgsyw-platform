# CMDB 配置管理

## 什么是 CMDB

CMDB (Configuration Management Database) 用于统一管理 IT 基础设施配置项（CI），例如服务器、应用、网络设备等，并记录它们之间的关联关系。它是整个平台的数据基础——设备、变更和统一任务都可以关联到 CMDB 中的配置项。

## 核心概念

### 配置项（CI）
一个可管理的 IT 资源实体，例如一台服务器、一个应用系统。每个 CI 有：
- **唯一标识**（实例 ID）
- **所属模型**（例如"主机"、"应用"）
- **属性**（IP 地址、负责人、操作系统等）
- **关联**（与其他 CI 的依赖或从属关系）

### 模型（Model）
定义一类 CI 的结构。例如"主机"模型规定了主机类 CI 应该有哪些字段（内网 IP、主机名、操作系统、环境等）。平台内置「主机」「应用」两个模型，管理员可新增。

### 关联（Relation）
描述两个 CI 之间的关系，例如"应用 A 部署在主机 B 上"、"应用 C 依赖应用 D"。关联是有方向的，并按语义分类（属于、运行、连接、依赖、部署等）。

## 推荐维护顺序

1. **先定义模型**：管理员在“CMDB → 模型管理”维护模型、属性分组、属性和关联定义。
2. **再维护实例**：业务人员在模型实例列表中创建或导入 CI。模型属性决定表单和列表列。
3. **补齐关联**：在实例详情的关联区域维护部署、依赖、连接等关系。
4. **核对影响范围**：变更或下线前从拓扑和影响分析确认上下游。
5. **关联业务记录**：在设备、变更文档或统一任务中引用 CI，让操作记录可回溯到资产。

模型和属性修改会影响该模型后续的编辑表单与列表展示；生产环境调整前，应先在少量实例上确认字段含义、是否必填和数据迁移方案。

## 数据如何流转

CMDB 保存资产主数据和关系，其他模块只保存关联到哪个 CI 的引用或快照：设备密码库从关联 CI 读取名称、IP 和设备类型；变更文档标记影响 CI；统一任务的 CI 字段按模板范围选择实例。CMDB 变更历史记录资产字段自身的修改，不能替代任务、审批或变更文档的审计记录。
