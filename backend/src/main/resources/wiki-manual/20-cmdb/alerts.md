# 告警中心

告警中心接收与配置项相关的告警（监控系统推送或手动录入），并进行分类处理与跟踪。

## 告警来源

- **外部系统推送**：通过 API 将监控系统（Zabbix、Prometheus 等）的告警推送到平台
- **手动创建**：运维人员手动录入发现的问题

## 告警列表

进入 **CMDB → 告警中心**：

- 列表展示所有告警，按严重度（critical / high / medium / low）标注颜色
- 多维过滤：按状态、严重度、时间、关联 CI、操作人
- 支持关键词搜索

## 告警字段

| 字段 | 说明 |
|------|------|
| 关联 CI | 与哪个配置项相关（必填） |
| 严重度 | critical / high / medium / low |
| 状态 | open（待处理）/ in_progress（处理中）/ resolved（已解决）/ closed（已关闭） |
| 标题 | 简短描述 |
| 详情 | 详细内容、告警消息原文 |
| 创建者 | 谁录入的 |
| 处理人 | 当前负责处理的人 |

## 告警处理

1. 点击某条告警进详情
2. 可以：
   - 更新状态（认领 → 处理中 → 已解决）
   - 添加备注（记录处理过程）
   - 关联其他 CI（如问题扩散）
   - 关闭告警
3. 所有操作都有记录

### 标准处理流程

1. 用严重度、状态和关联 CI 筛选待处理告警，优先处理 critical/high。
2. 打开详情确认告警来源、首次发生时间、关联 CI 和原始内容。
3. 认领或更新为“处理中”，避免多人重复处理；在备注中记录判断、操作和下一步。
4. 如影响范围扩大，补充关联 CI，并到 CMDB 拓扑检查上下游。
5. 验证恢复后更新为“已解决”；需要保留一段观察期时按团队规范关闭。

状态更新只表示告警处置进度，不会自动执行修复命令。需要排障、巡检或整改材料时，可创建统一任务并在任务中关联同一 CI。

## 告警统计

告警中心首页展示：
- **今日新增 / 待处理 / 已解决** 数量
- **趋势图表** — 每日新增/解决告警数
- **Top 告警 CI** — 哪些配置项最频繁报警

## 通知

重要告警可配置站内信或邮件通知（需管理员配置）。

## 常见问题

**没有收到外部告警**：检查系统管理中的监控集成是否启用、地址和同步间隔是否正确，再检查外部系统是否能访问平台。

**无法关联 CI**：先在 CMDB 确认实例存在且你有查看权限；告警不应使用自由文本替代关联资产。

**关闭后又出现**：告警恢复与再次触发由外部监控状态决定。应检查原始指标和告警规则，而不是只反复修改平台状态。

## 权限

- `cmdb_alert:create` — 创建告警
- `cmdb_alert:update` — 处理告警
- `cmdb_alert:delete` — 删除告警（一般仅管理员）
