# 用户与权限管理

管理员通过本模块管理用户、用户组、角色和权限分配。

## 用户管理

进入用户管理页：

- **新建用户**：填写用户名、姓名、初始密码，分配所属组和角色
- **编辑用户**：修改姓名、所属组、角色、启用/停用
- **重置密码**：为用户重置登录密码
- **停用用户**：停用后无法登录（软删除，数据保留）

### 创建或调整用户的步骤

1. 先确认该用户应归属的用户组和工作职责。
2. 在“用户管理”点击新建，填写用户名、姓名、初始密码和所属组。
3. 分配满足职责的最小角色；不要为方便操作直接授予超级管理员。
4. 保存后让用户重新登录，确认只看到应有菜单并能完成必要动作。
5. 人员调岗、离职或临时权限结束时，调整组和角色或停用用户；历史任务、审批和审计仍保留原记录。

重置密码后应通过受控渠道通知本人，不要在任务评论、Wiki 或共享文件中发送明文密码。

## 用户组管理

用户组用于按团队/部门组织用户：

- 新建、编辑、删除用户组
- 每个用户归属一个组
- 很多模块支持"组级隔离"——组级用户只能看本组数据

用户组同时用于数据范围、任务计划分派、审批候选和文件/Wiki 授权。调整成员前先确认对待执行任务、值班计划和审批队列的影响；历史任务按生成或执行时快照保留，不会因调组而改写历史统计。

## 角色管理

角色是权限的集合。平台预置 5 个角色：

| 角色 | 范围 | 说明 |
|------|------|------|
| 超级管理员 | 全平台 | 所有权限 |
| 管理员 | 租户 | 租户级所有权限 |
| 组长 | 组 | 本组管理 + 审批 |
| 组员 | 组 | 基本读写 |
| 只读 | 组 | 仅查看 |

可以：
- 新建自定义角色
- 编辑角色的权限集合（勾选该角色拥有哪些 `资源:动作`）
- 给用户分配角色

### 配置角色的步骤

1. 先创建角色名称、编码和适用范围，明确它服务的岗位。
2. 打开角色卡片的“配置权限”，按资源分组勾选需要的动作。
3. 保存后仅给试点用户分配，验证菜单、列表范围、创建按钮和敏感操作。
4. 验证无误后再批量分配给同岗位用户，并记录角色用途。

内置角色由系统维护，不能随意删除。需要差异化能力时创建自定义角色，不要修改无关岗位正在使用的公共角色。

## 权限分配

权限以 `资源:动作` 形式存在，例如：

- `device:view_password` — 查看设备密码
- `wiki:publish` — 发布 Wiki 页面
- `cmdb_instance:import` — CMDB 批量导入

在角色管理中勾选权限，即把权限授予该角色；用户通过角色获得权限。

## 统一任务权限

统一任务按职责拆分权限，管理员应按实际岗位授予：

| 职责 | 需要具备的能力 |
|---|---|
| 执行人 | 查看任务、填写草稿、上传附件、提交任务 |
| 审批人 | 在“我的工作”的待审批中查看提交内容并通过、退回或终止 |
| 任务创建者 | 创建一次性任务，查看自己发起任务的进度 |
| 模板管理员 | 创建、编辑、校验、发布和停用任务模板 |
| 计划管理员 | 创建、预览、激活、暂停和归档任务计划 |
| 统计管理员 | 配置统计看板、指标、目标、订阅和自动化规则 |
| 日历设置管理员 | 维护排班和节假日历 |

“查看任务”“维护模板”“维护计划”“查看统计”“维护统计”和“日历设置”是彼此独立的授权范围。不要因为某人能审批，就默认授予其创建模板或查看全部统计数据的权限。敏感字段和附件还会受任务本身的数据范围限制。

## 实践建议

- 遵循最小权限原则——只给必要的权限
- 敏感权限（查看密码、备份恢复、删除）谨慎分配
- 用角色批量管理，避免逐个用户配置

## 审计

所有用户、权限的变更都会记录到审计日志，可追溯谁在什么时候改了权限。

## 授权排查顺序

1. 确认用户处于启用状态且已重新登录。
2. 确认用户所属组正确，且该组没有被归档或限制。
3. 检查用户持有的角色和角色中的 `资源:动作` 权限。
4. 检查业务对象本身的范围或 ACL，例如任务、文件夹、Wiki 页面和设备组权限。
5. 最后查看审计日志确认最近是否发生授权调整。

角色权限允许访问功能，并不自动绕过业务数据范围；例如拥有任务统计入口权限，也只能看到自己有权查看的源任务数据。
