# 系统管理

系统管理面向管理员，包含用户与权限、系统配置、数据备份等平台级功能。普通用户通常无需关心本章。

## 功能导航

- **[[用户与权限管理]]** — 用户、用户组、角色、权限分配
- **[[系统配置与备份]]** — 邮件/水印等系统配置，数据备份与恢复

## 谁能访问

系统管理功能默认仅 **超级管理员** 和 **管理员** 可用。具体以角色权限分配为准。

## 管理员的推荐顺序

1. 建立用户组，明确每个团队的负责人和成员。
2. 创建或维护角色，再按资源和动作配置权限。
3. 创建用户并分配组、角色，使用最小权限原则。
4. 配置邮件、监控和水印等系统参数；先在维护窗口验证。
5. 定期查看审计日志，重大操作前创建备份，恢复前再次备份。

不要把“管理员”当成所有人日常操作的替代角色。设备密码、备份恢复、ACL、任务统计和流程配置属于高风险能力，应按职责拆分。

## 权限模型概览

平台采用 RBAC（基于角色的访问控制）：

```
资源 → 权限(资源:动作) → 角色 → 用户
```

- **资源**：一类可管理对象（用户、设备、CMDB、文件等）
- **权限**：资源上的某个动作（如 `device:view_password`）
- **角色**：一组权限的集合
- **用户**：被分配一个或多个角色

用户通过角色获得权限，管理员通过调整角色权限来控制每个人能做什么。详见 [[用户与权限管理]]。

## 操作后的系统行为

- 用户或角色变更会影响下一次权限校验；用户重新进入页面或重新登录后应确认菜单和动作是否符合预期。
- 组变更会影响组范围数据可见性、任务计划分派和部分审批候选关系，但不会重写历史任务的组织快照。
- 配置、备份、恢复和 ACL 操作都会进入审计记录，应记录变更目的和审批依据。
