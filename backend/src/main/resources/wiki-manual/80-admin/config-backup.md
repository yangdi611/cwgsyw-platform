# 系统配置与备份

管理员通过本模块维护平台级配置和数据备份。

## 系统配置

系统配置页可设置：

- **邮件（SMTP）配置** — 配置发件服务器，让平台能发送通知邮件（审批结果、告警等）
- **水印配置** — 页面水印的开关与内容
- 其他平台级参数

配置实时生效，修改后无需重启。

### 配置操作步骤

1. 进入“系统管理 → 系统配置”，在左侧选择邮箱配置、监控集成或文档水印。
2. 填写参数并保存。保存失败时不要反复提交密码字段，先核对格式、网络和权限。
3. 邮箱配置需确认是否启用、服务器、端口、用户名、密码、发件人、发件名称和 SSL 是否匹配服务商要求。
4. 监控集成需确认是否启用、Prometheus 地址无多余尾部路径、同步间隔满足运行要求。
5. 水印需确认启用状态、文字、透明度、角度和位置；先选择不影响阅读的样式。

保存配置不代表外部服务一定可达。邮件或监控未按预期工作时，应检查服务地址、网络、账号权限和后端日志。

## 数据备份与恢复

备份功能对平台数据做全量备份/恢复，仅管理员可用。

### 立即备份
进入 **系统管理 → 备份**，点"立即备份"：
- 系统打包数据库 + 文件存储
- 生成一个备份文件
- 备份过程同步执行，大数据量时请耐心等待

备份完成后应在备份记录中核对状态、创建时间、大小和创建人；失败记录会显示错误信息。只有状态成功的备份可作为恢复点。

### 上传备份
可以把本地已有的备份文件上传入库（用于迁移或恢复历史备份）。

### 下载备份
点击某条备份记录可下载备份文件，妥善保存到安全位置。

### 恢复
点"恢复"会用所选备份覆盖当前数据：

> ⚠️ 恢复是高风险操作，会覆盖现有数据。请务必确认后再操作，建议恢复前先做一次当前数据的备份。

恢复完成后建议重启服务以清除缓存。

### 恢复操作步骤

1. 先通知相关用户停止写入，并记录计划恢复的备份时间点。
2. 创建一次当前状态的备份，作为回退点。
3. 在备份列表核对文件名、时间、大小和状态，确认选择正确记录。
4. 点击恢复并完成二次确认；恢复期间不要继续创建任务、修改 CI 或上传文件。
5. 完成后检查后端健康、登录、关键业务数据、文件访问和通知配置；必要时重新登录以刷新会话。

上传本地备份前只接受平台生成且受信任的 `.tar.gz` 文件。不要上传来源不明的压缩包；备份包含数据库和文件数据，应按敏感资料进行存储和传输。

### 自动轮转
系统自动清理超过保留期（默认 30 天）的旧备份，避免占用过多空间。

## 备份建议

- 重大变更前手动备份一次
- 定期下载备份到平台之外的安全存储
- 恢复操作前再次确认备份内容和时间点

## 审计与排查

备份创建、下载、恢复和删除均应由具备对应权限的管理员执行，并在审计日志中留存。若备份失败，先查看失败状态和错误信息，确认磁盘空间、数据库、对象存储和后端服务正常后再重试；不要删除唯一成功备份来腾出空间。

## 权限

| 权限 | 能做什么 |
|------|---------|
| `backup:create` | 创建/上传备份 |
| `backup:read` | 查看/下载 |
| `backup:restore` | 恢复 |
| `backup:delete` | 删除备份 |

以上权限默认仅超级管理员/管理员拥有。
