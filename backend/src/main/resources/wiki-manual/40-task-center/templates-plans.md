# 任务模板与计划

本章面向模板管理员和计划管理员，说明如何把“让谁在何时填写什么、提交什么、谁审批”配置成可复用任务。

## 一、创建任务模板

路径：**任务中心 → 任务模板 → 新建模板**。

1. 填写模板编码、名称、分类和说明。
2. 选择适用范围。范围决定谁可以管理或使用此模板，应遵循最小授权原则。
3. 创建后系统生成 `v1` 草稿，并进入模板设计器。
4. 在设计器中配置执行说明、表单字段和字段属性。
5. 使用“执行人预览”和“审批人预览”检查展示效果。
6. 点击“保存”，再点击“校验”。解决全部校验问题后，点击“发布并锁定”。

模板编码应使用稳定、可读的英文小写标识，例如 `database_daily_inspection`。编码用于区分模板，不建议在发布后通过新建相似编码来规避版本管理。

### 设计表单

设计器分为三栏：左侧字段组件库，中间表单画布，右侧字段配置。点击左侧字段把它加入画布；在画布中选中字段后，通过右侧面板设置标题、字段编码、必填、敏感、校验、条件和统计语义。

| 类别 | 可用字段 | 典型用途 |
|---|---|---|
| 基础输入 | 单行文本、多行文本、富文本、数字、金额、百分比 | 说明、处理结果、次数、工时、金额 |
| 选择 | 单选、多选、开关、评分、标签 | 状态、风险等级、是否异常、分类 |
| 时间 | 日期、日期时间、时间段、时长 | 巡检日期、窗口、处理耗时 |
| 组织 | 人员、用户组、角色 | 负责人、协作组、值班角色 |
| 运维对象 | CI 范围、关联对象 | 选择受控 CI、关联业务对象 |
| 结构化 | 表格、重复区块 | 多条巡检明细、故障列表、分项记录 |
| 文件 | 文件、图片 | 回执、截图、报告、现场照片 |
| 计算 | 公式字段、引用汇总 | 完成率、日报汇总、周报差异 |
| 布局 | 分组标题、说明文本 | 表单分段和操作指引 |

### 配置字段时的要点

- **字段编码**：字段的稳定标识。新字段可修改；已保存或已被使用的字段不要随意变更编码，否则历史数据和统计绑定会失去可读性。
- **必填和校验**：对必须提交的内容打开“必填”；通过校验配置限制数值、选项或行数。提交时系统会统一校验。
- **条件显示**：用受控条件表达式控制字段何时显示或必填，例如“是否异常”为“是”时显示异常说明。不要把业务规则写在说明文字中而不配置校验。
- **公式**：只使用受控公式表达式和字段引用，适合比例、合计等可解释计算；不能填写任意脚本或 SQL。
- **敏感字段**：敏感字段不能形成统计事实或导出，请只对确有必要的数据启用；审批、执行和附件访问仍受权限控制。
- **附件**：文件和图片字段可设为必填。执行人会在该字段位置上传，审批意见也可关联到附件。
- **表格和重复区块**：用于同类多条记录。需要统计时，应在表格内明确配置要统计的数字列和单位。

### 配置统计语义

需要进入统计中心的字段，应在右侧“统计语义”中启用统计，并选择角色：

- **指标**：需要求和、平均、最小、最大或计数的值，如巡检次数、时长、评分。
- **维度**：用于分组、筛选或下钻，如组、人员、CI、日期、选项和标签。
- **筛选**：仅用于限定分析范围。
- **明细**：在结果中展示原始文字或结构化内容。

系统只显示该字段类型合法的聚合方式。数字、金额、百分比、评分和时长通常支持合计、平均、最小、最大、计数和去重计数；选项、人员、组、CI 等通常支持计数和去重计数；文件和图片适合按数量汇总。

## 二、版本、发布与停用

每个模板有多个版本。

1. `草稿`可以编辑、预览、校验和发布。
2. `已发布`版本是不可变快照，不能直接编辑。
3. 需要调整时，在模板详情点击“创建下一草稿版本”，完成修改后再发布。
4. 新计划或新任务使用已发布版本；已经生成的任务继续使用原版本，历史提交、附件和统计口径不被改写。
5. 不再用于新任务的版本可停用；是否允许归档取决于是否仍有正式引用。

发布前至少核对：执行说明是否清楚、必填字段是否完整、附件是否符合要求、条件/公式是否校验通过、统计字段是否配置了正确单位和聚合、审批人预览是否能看到必要信息。

## 三、创建任务计划

路径：**任务中心 → 任务计划 → 新建计划**。计划编辑器分四步，建议按顺序完成并在最后预览。

### 1. 基础信息

- 填写计划名称和说明。
- 选择一个已发布模板版本。
- 选择审批方案，或明确选择“无需审批”。有审批的任务会在执行人提交后进入“我的工作 → 待审批”。

计划激活时，系统会固化所选模板和审批方案版本。修改模板或审批方案后，不会追溯改变已生成任务。

### 2. 周期与截止时间

支持以下周期：

| 类型 | 适合场景 |
|---|---|
| 一次性 | 预先计划的一次专项检查 |
| 每日 | 日报、每日巡检、每日确认 |
| 每周 | 周报、周例行检查 |
| 每月 / 每季度 / 每半年 / 每年 | 定期汇报、盘点、合规检查 |
| 高级 Cron | 需要精确调度表达式的固定规则；仅授予熟悉 Cron 的管理员使用 |
| 节假日前后 | 节前检查、节后恢复等依赖平台节假日历的任务 |

同时设置生效日期、可选结束日期、截止偏移小时数、提前生成天数和优先级。提前生成不是提前截止：它决定任务多久前出现在执行人工作台，截止时间仍按任务发生时间和截止偏移计算。

### 3. 执行对象与 CI

生成模式决定同一周期会生成几份任务：

- **每人一份**：团队每位成员分别完成，例如个人日报。
- **每组一份**：以组为单位协作完成，例如值班组周报。
- **共享一份**：多人围绕同一任务协作填写。
- **单人一份**：指定某一执行人。

按生成模式选择用户组或人员。保存前先确认人员/组的有效性，避免生成无人认领的任务。

CI 范围选择器支持混合多选：模型组、具体模型和单个 CI 实例。例如可同时选择“数据库组”“MySQL 模型”和某台 CI。系统会解析、去重并在预览中显示实际命中范围。计划后续生成的任务会使用当时的范围；历史任务和提交保留自身快照。

### 4. 提醒与预览

配置截止前提醒、逾期提醒和升级策略。提醒是辅助机制，不能替代任务本身的截止时间和审批要求。

点击“预览”后，检查未来实例的发生时间、执行人、截止时间和 CI 命中数量。预览无误后保存计划；在任务计划列表中点击“激活”，任务才会按规则生成。运行中的计划需要调整时先暂停，修改并复核后再激活。

## 四、创建一次性任务

适用于临时安排，不需要先建立长期周期计划。

路径：**运维日历 → 新建任务**，也可在某日的日历详情中发起。

1. 填写任务标题和说明。
2. 选择已发布任务模板和执行人。
3. 设置开始时间和截止时间，截止时间不得早于开始时间。
4. 点击“创建任务”，系统进入该任务详情页。
5. 执行人后续按模板填写和提交，和周期任务使用同一条流程。

一次性任务同样会出现在运维日历、任务列表和“我的工作”，并保留模板版本、附件和审批追溯。

## 五、计划维护建议

- 先用少量执行人和短期范围做预览，再激活全组周期计划。
- 一个模板只描述一种稳定的填报结构；日报与周报字段、统计维度差异较大时，应使用不同模板。
- 报表的“自动汇总值”和“人工上报值”应分别建字段或指标来源，避免重复累加。
- 暂停计划会停止后续生成，不会删除已生成任务；应继续处理已生成的待办。
- 完全不再使用的计划可归档；不要直接删除仍有任务历史的配置。
